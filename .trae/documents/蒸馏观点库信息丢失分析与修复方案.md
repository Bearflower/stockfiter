# 蒸馏观点库信息丢失分析与修复方案

## 问题现象

新增 11 篇博文并执行增量蒸馏后，观点库.jsonl 中的 20 条观点仍然是通用投资原则（如"资产配置是唯一免费午餐"、"控制回撤比追求收益更重要"），没有反映出新增博文（特别是 6 月三篇）中的独特观点。

### 具体丢失的内容

以 `2026年6月长赢投资计划（三）（卖出部分）.md` 为例：

| 原文关键内容 | 蒸馏摘要 | 丢失了什么 |
|------------|---------|-----------|
| 买得极低（2016-2018年买入）却6年不赚钱（2024年），到2026年才83%卖出 | "强调在A股必须买得足够便宜才能赚钱" | 丢失了"买得足够便宜也要熬8年"的时间维度，丢失了"买高估会生不如死"的对比警示 |
| "买得那么低尚且那么难，买高了会怎样？" | 未体现 | 丢失了递进式的警示逻辑 |
| 如果2015年买入，11年收益率仅14%，最大回撤50% | 未体现 | 丢失了具体的对比数据 |
| "市场上又出现估值80+的宽基指数了" | 未体现 | 丢失了当前市场背景判断 |

### 6月（二）丢失的内容

| 原文关键内容 | 蒸馏摘要 | 丢失了什么 |
|------------|---------|-----------|
| "红利指数在A股超越宽基，是适合个人投资者的品种" | 基本保留 | - |
| "这次卖出不是减仓红利，而是换仓到成本更低的同类指数" | 未体现 | 丢失了"卖出不等于看空"的关键操作逻辑 |

## 根因分析

### 链路总览

```
blog原文 → [summarizer] → 摘要(100字) → [analyzer: 294篇→分批×3→合并] 
→ 核心观点矿脉.md(5709字) + 金句库.md(4079字) → [opinion_extractor] 
→ 观点库.jsonl(20条固定)
```

### 环节1：summarizer — 摘要丢失细节

- **相关文件**: `scripts/distill/summarizer.py` 第19行 `_SUMMARIZE_PROMPT`
- **问题**: 要求"不超过100字概括核心观点"。对于有递进逻辑的博文（如6月（三）的"买得便宜→但也要熬8年→买高估的更惨"），100字容量不足以保留完整的因果链，LLM 倾向于选择最浅层的结论（"必须买便宜"）。
- **影响**: 一旦摘要丢失了原文的关键信息，后续所有环节都无法弥补。

### 环节2：analyzer — 低频新观点被过滤（**核心问题**）

- **相关文件**: `scripts/distill/analyzer.py` 第112-138行 `build_analysis_prompt`
- **问题**: Prompt 要求"提炼出他最核心、最反复强调的10个观点"。294篇中11篇新文章仅占3.7%，其独特内容在提取"反复强调"的观点时被自然过滤。
- **分批机制**(第172-208行): 3批各处理~100篇，每批分别提取一次，然后merge prompt合并3批结果。新文章在每批中更分散，进一步降低了出现概率。
- **无"近期新观点"的识别逻辑**: 代码对所有文章一视同仁，没有给新文章更高的权重。

### 环节3：opinion_extractor — 固定20条+只看浓缩产物

- **相关文件**: `scripts/distill/opinion_extractor.py` 第26-48行 `EXTRACT_PROMPT_TEMPLATE`
- **问题**: 从已经丢失细节的"核心观点矿脉"和"金句库"中提取，输入已有信息缺失。
- **固定20条**: 只提取最高频的通用金句，没有"近期新观点"的独立通道。

---

## 修复方案

### 方案A（推荐）：在 opinion_extractor 中增加"近期新观点"提取通道

**思路**：不修改已有的整个链路（防止影响通用观点质量），而是新增一个独立环节，直接从**新增博文的原文**或**新增博文的摘要**中提取独特观点，合并入观点库。

| 修改文件 | 修改内容 |
|---------|---------|
| `scripts/distill/opinion_extractor.py` | 新增 `extract_new_opinions(config, new_files)` 函数，直接读取新增博文原文，提取其中独特的市场判断/操作逻辑 |
| `scripts/distill/main.py` cmd_update | 在调用 `extract_opinions` 之后，传入新增文件列表，调用 `extract_new_opinions` 提取新观点，合并写入观点库 |
| `scripts/distill/config.yaml` | 为新增观点通道增加配置项 |

**优点**：
- 不影响现有通用观点提取（兼容性最好）
- 直接从原文提取（避免摘要丢失的信息）
- 可针对性提取近期市场判断（如"红利超越宽基"、"市场上又出现高估品种"）
- 新增代码量少，修改范围小

**缺点**：
- 观点库.jsonl 中通用观点和新观点混在一起，缺乏区分

### 方案B（激进）：修改 analyzer prompt

**思路**：修改 `build_analysis_prompt`，要求LLM同时提取"高频通用观点"和"近期新增独特观点"。

| 修改文件 | 修改内容 |
|---------|---------|
| `scripts/distill/analyzer.py` build_analysis_prompt | 在现有提示中添加要求："请同时关注近期新增文章中的独特观点，即使它们在全部文章中只出现1-2次" |
| `scripts/distill/main.py` cmd_update | 在调用 analyze 时传入新增文件列表，让 analyzer 知道哪些是新增的文章 |

**缺点**：
- analyzer 的输入仍然是摘要而非原文，丢失的信息无法恢复
- 改造幅度大，可能影响分析的稳定性
- 需要修改分批机制和 merge prompt

### 方案C（综合推荐）：方案A + 改进摘要质量

**思路**：在实施方案A的基础上，同时优化 summarizer 的 prompt，让摘要保留更完整的递进逻辑。

| 修改文件 | 修改内容 |
|---------|---------|
| `scripts/distill/summarizer.py` | 将摘要上限从100字提升到150字；在 prompt 中增加要求："如果有对比论证或递进逻辑，请完整保留" |
| `scripts/distill/opinion_extractor.py` | 新增 `extract_new_opinions` 从新增原文提取观点 |
| `scripts/distill/main.py` cmd_update | 在 update 流程中调用新观点提取 |
| `scripts/distill/config.yaml` | 为摘要长度和新观点提取增加配置项 |

## 验证方法

1. 修改后重新执行 `python3 scripts/distill/main.py update`（需重置6月文件的状态）
2. 检查观点库.jsonl 中是否包含：
   - "在A股买得便宜也要做好长期等待的准备" 
   - "红利指数在A股长期超越宽基"
   - "卖出某品种不等于看空该品种，换仓是优化持仓"
   - "当前市场出现高估值品种，需警惕"
3. 确保原有的通用观点（20条中的前10条）不被覆盖或删除
