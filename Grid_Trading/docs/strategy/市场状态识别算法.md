## 1. 概述

### 1.1 算法目标

市场状态识别算法是网格交易系统的核心模块，负责：
- 量化分析市场当前处于震荡、趋势还是强趋势状态
- 结合多时间框架（15m/1h/4h）进行交叉验证，减少假信号
- 输出最终市场状态及趋势强度系数，供后续网格参数计算使用

### 1.2 算法架构

```
┌─────────────────────────┐
│   获取多时间框架K线数据   │
│   (15m / 1h / 4h)       │
└────────────┬────────────┘
             ↓
┌─────────────────────────┐
│   计算技术指标           │
│   ADX(14), EMA(20,50),  │
│   ATR(14), ATR_smooth   │
└────────────┬────────────┘
             ↓
┌─────────────────────────┐
│   单时间框架状态判定     │
│   (1h为主，4h辅助)      │
└────────────┬────────────┘
             ↓
┌─────────────────────────┐
│   多时间框架交叉确认     │
│   输出最终状态 + k值     │
└─────────────────────────┘
```

### 1.3 各时间框架职责

| 时间框架 | 核心作用 | 巡检/触发频率 | 输出指标 |
|----------|---------|----------------|---------|
| **15分钟** | 边界突破检测：检测价格是否突破网格边界、是否触发上移/下移条件 | 每15分钟（可简化为每小时获取最新值） | 最新标记价格 |
| **1小时** | 主交易周期：计算ADX/EMA/ATR，判断市场状态 | 每小时整点K线收盘后 | ADX、EMA(20)、EMA(50)、ATR |
| **4小时** | 趋势过滤器：确认大方向，防止1h假信号 | 每小时获取最新4hK线值（可与1h同步） | ADX、EMA(20)、EMA(50) |

## 2. 技术指标计算逻辑

### 2.1 ADX（平均趋向指数）

#### 2.1.1 指标说明

ADX（Average Directional Index）用于衡量趋势强度，取值范围 0~100。
- **ADX < 20**: 市场无趋势，处于震荡状态
- **ADX ≥ 25**: 市场有明确趋势
- **ADX ≥ 40**: 强趋势，应暂停网格避免追涨杀跌

#### 2.1.2 计算步骤

**第1步：计算真实波幅 TR（True Range）**

```
TR = max(最高价 - 最低价, |最高价 - 前收盘价|, |最低价 - 前收盘价|)
```

**第2步：计算方向移动 +DM 和 -DM**

```
up_move = 当前最高价 - 前最高价
down_move = 前最低价 - 当前最低价

if up_move > down_move and up_move > 0:
    +DM = up_move
else:
    +DM = 0

if down_move > up_move and down_move > 0:
    -DM = down_move
else:
    -DM = 0
```

**第3步：平滑 +DM 和 -DM（使用 Wilder 平滑，周期 = 14）**

```
+DM_smooth[0] = 前14根K线的 +DM 之和
+DM_smooth[i] = +DM_smooth[i-1] - (+DM_smooth[i-1] / 14) + +DM[i]

-DM_smooth[0] = 前14根K线的 -DM 之和
-DM_smooth[i] = -DM_smooth[i-1] - (-DM_smooth[i-1] / 14) + -DM[i]
```

**第4步：计算 +DI 和 -DI（方向指标）**

```
+DI = (+DM_smooth / TR_smooth) × 100
-DI = (-DM_smooth / TR_smooth) × 100
```

其中 `TR_smooth` 的计算方式与 +DM_smooth 相同，使用 Wilder 平滑。

**第5步：计算 DX（趋向指数）**

```
DX = |+DI - -DI| / (+DI + -DI) × 100
```

**第6步：计算 ADX（DX 的 Wilder 平滑，周期 = 14）**

```
ADX[0] = 前14根K线的 DX 平均值
ADX[i] = (ADX[i-1] × 13 + DX[i]) / 14
```

#### 2.1.3 关键参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| ADX周期 | 14 | 标准周期，不建议修改 |
| 震荡阈值 | 20 | ADX < 20 判定为震荡 |
| 趋势阈值 | 25 | ADX ≥ 25 判定为趋势 |
| 强趋势阈值 | 40 | ADX ≥ 40 触发强趋势暂停 |

### 2.2 EMA（指数移动平均线）

#### 2.2.1 指标说明

EMA（Exponential Moving Average）对近期数据赋予更高权重，比简单移动平均更敏感。

系统使用两条EMA线：
- **快线 EMA(20)**：反映短期价格方向
- **慢线 EMA(50)**：反映长期价格方向

通过两条EMA的相对位置判断趋势方向。

#### 2.2.2 计算公式

**平滑系数 α：**

```
α = 2 / (周期 + 1)
```

**EMA 计算：**

```
EMA[0] = 前N个收盘价的简单平均值（SMA）
EMA[i] = 收盘价[i] × α + EMA[i-1] × (1 - α)
```

**快线 EMA(20)：**

```
α_fast = 2 / (20 + 1) = 0.0952
EMA_fast[i] = 收盘价[i] × 0.0952 + EMA_fast[i-1] × 0.9048
```

**慢线 EMA(50)：**

```
α_slow = 2 / (50 + 1) = 0.0392
EMA_slow[i] = 收盘价[i] × 0.0392 + EMA_slow[i-1] × 0.9608
```

#### 2.2.3 趋势方向判定

| 条件 | 判定 |
|------|------|
| EMA(20) > EMA(50) | 上升趋势方向 |
| EMA(20) < EMA(50) | 下降趋势方向 |
| EMA(20) ≈ EMA(50) | 无明确方向（结合ADX进一步判断） |

#### 2.2.4 关键参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 快EMA周期 | 20 | 短期方向判断 |
| 慢EMA周期 | 50 | 长期方向确认 |

### 2.3 ATR（平均真实波幅）

#### 2.3.1 指标说明

ATR（Average True Range）衡量市场波动率，用于计算网格宽度、步长、止损距离等。

#### 2.3.2 计算步骤

**第1步：计算 TR（True Range）**（同上）

```
TR = max(最高价 - 最低价, |最高价 - 前收盘价|, |最低价 - 前收盘价|)
```

**第2步：计算原始 ATR（Wilder 平滑，周期 = 14）**

```
ATR[0] = 前14根K线的 TR 平均值
ATR[i] = (ATR[i-1] × 13 + TR[i]) / 14
```

**第3步：计算平滑 ATR（对原始 ATR 再做一次 EMA 平滑，周期 = 14）**

```
ATR_smooth = EMA(ATR(14), 14)
```

即对第2步计算出的 ATR 序列再做一次 14 周期的指数移动平均。

#### 2.3.3 为什么需要双重平滑？

单次 ATR 计算虽然已经做了 Wilder 平滑，但在极端行情下仍可能出现较大跳动。通过再做一次 EMA 平滑，可以：
- 过滤异常波动，避免网格宽度突然变化
- 提供更稳定的波动率参考值
- 减少参数频繁调整的频率

#### 2.3.4 基准 ATR

系统还维护一个**基准 ATR**，用于网格数量的动态调整：

```
基准ATR = 过去90天 ATR(14) 的滚动平均值
```

- 使用滚动窗口，每天更新一次
- 窗口大小：90天
- 用途：计算网格数量 N = 30 × (基准ATR / 当前ATR_smooth)

#### 2.3.5 关键参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| ATR周期 | 14 | 标准周期 |
| ATR平滑周期 | 14 | 对ATR再做一次EMA平滑 |
| 基准ATR窗口 | 90天 | 滚动窗口均值 |

## 3. 多时间框架状态判定规则

### 3.1 单时间框架状态判定（以1h为例）

```python
def single_tf_state(adx_1h, ema_fast_1h, ema_slow_1h, prev_state):
    """
    单时间框架状态判定
    
    参数:
        adx_1h: 1小时周期的ADX值
        ema_fast_1h: 1小时周期的EMA(20)
        ema_slow_1h: 1小时周期的EMA(50)
        prev_state: 上一个状态（用于灰色区域处理）
    
    返回:
        "震荡", "上升趋势", "下降趋势", 或 "强趋势"
    """
    # 强趋势判定（最高优先级）
    if adx_1h >= 40:
        return "强趋势"
    
    # 震荡判定
    elif adx_1h < 20:
        return "震荡"
    
    # 趋势判定
    elif adx_1h >= 25:
        if ema_fast_1h > ema_slow_1h:
            return "上升趋势"
        else:
            return "下降趋势"
    
    # 灰色区域（20 ≤ ADX < 25）
    else:
        # 保持前一状态，避免频繁切换
        return prev_state
```

### 3.2 多时间框架交叉确认规则

系统结合 1h 和 4h 的状态，通过以下规则输出最终状态：

| 1h 状态 | 4h 状态 | 最终状态 | 网格模式 | 移动功能 |
|----------|---------|----------|----------|----------|
| 震荡 | 任意 | **震荡** | 双向中性 | 无 |
| 上升趋势 | 上升趋势 | **上升趋势** | 偏多非对称 | 启用上移 |
| 上升趋势 | 震荡 | **震荡（降级）** | 双向中性 | 无 |
| 上升趋势 | 下降 | **震荡（降级）** | 双向中性 | 无 |
| 下降趋势 | 下降趋势 | **下降趋势** | 偏空非对称 | 启用下移 |
| 下降趋势 | 震荡 | **震荡（降级）** | 双向中性 | 无 |
| 下降趋势 | 上升 | **震荡（降级）** | 双向中性 | 无 |
| 任意 | **强趋势（ADX≥40）** | **强趋势暂停** | 不创建/暂停 | 无 |

#### 3.2.1 规则解读

**规则1：1h震荡 → 最终震荡**

无论4h是什么状态，只要1h是震荡，最终就是震荡。原因：1h是主交易周期，如果短期没有趋势，即使长期有趋势，也不适合做趋势网格。

**规则2：1h趋势 + 4h同向 → 确认趋势**

1h和4h方向一致，说明大趋势和小趋势共振，是可靠的趋势信号。

**规则3：1h趋势 + 4h反向/震荡 → 降级为震荡**

1小时出现趋势但4小时不确认，可能是假突破或短期波动，降级处理更安全。

**规则4：4h强趋势 → 强制暂停**

无论1h是什么状态，只要4小时ADX≥40，说明大级别趋势极强，此时不应参与网格，避免追涨杀跌。

### 3.3 状态确认机制（保守模式）

为避免状态频繁切换导致的频繁调整，系统引入**连续确认机制**：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 状态确认次数 | 3 | 连续3次巡检输出相同状态才确认切换 |
| 确认周期 | 3小时 | 每次巡检间隔1小时，3次=3小时 |

```python
class StateConfirmation:
    def __init__(self, confirm_count=3):
        self.confirm_count = confirm_count
        self.state_history = []
    
    def update(self, current_state):
        """更新状态历史"""
        self.state_history.append(current_state)
        # 只保留最近 confirm_count 条记录
        if len(self.state_history) > self.confirm_count:
            self.state_history = self.state_history[-self.confirm_count:]
    
    def is_confirmed(self):
        """检查状态是否已确认（连续N次相同）"""
        if len(self.state_history) < self.confirm_count:
            return False
        return all(s == self.state_history[-1] for s in self.state_history)
    
    def get_confirmed_state(self):
        """返回已确认的状态"""
        if self.is_confirmed():
            return self.state_history[-1]
        return None
```

#### 3.3.1 极端情况快速通道

在某些极端情况下，系统应跳过确认机制，立即切换状态：

| 场景 | 动作 |
|------|------|
| 价格突破网格范围 > 10% | 立即调整为对应状态 |
| ATR 变化 > 50% | 立即重新评估状态 |
| ADX 从 < 20 跳变到 > 40 | 立即进入强趋势暂停 |

| 状态变更 | 系统动作 |
|----------|---------|
| 震荡 → 趋势 | 计算新网格参数（非对称），推送趋势网格配置 |
| 趋势 → 震荡 | 计算新网格参数（中性），推送震荡网格配置 |
| 任意 → 强趋势暂停 | 推送暂停指令，建议终止当前网格 |
| 强趋势暂停 → 任意 | 重新计算网格参数，推送新配置 |

## 5. 趋势强度系数 k

### 5.1 计算公式

当市场处于**上升趋势**或**下降趋势**时，计算趋势强度系数 k：

```
k = min(0.5, max(0, (ADX_1h - 25) / 30))
```

### 5.2 参数说明

| 参数 | 说明 |
|------|------|
| ADX_1h | 1小时周期的ADX值 |
| 25 | 趋势确认阈值（ADX≥25才进入趋势） |
| 30 | 归一化系数（将ADX 25~55的范围映射到 0~1） |
| 0.5 | 最大值限制（避免趋势过强时步长过大） |

### 5.3 k 值示例表

| ADX_1h | 计算过程 | k 值 | 趋势强度 |
|--------|---------|------|---------|
| 20 | max(0, (20-25)/30) = 0 | 0.00 | 无趋势（震荡） |
| 25 | max(0, (25-25)/30) = 0 | 0.00 | 趋势刚确认 |
| 28 | max(0, (28-25)/30) = 0.1 | 0.10 | 弱趋势 |
| 32 | max(0, (32-25)/30) = 0.233 | 0.23 | 中等趋势 |
| 37 | max(0, (37-25)/30) = 0.4 | 0.40 | 强趋势 |
| 40 | max(0, (40-25)/30) = 0.5 | 0.50 | 强趋势（上限） |
| 50 | max(0, (50-25)/30) = 0.833 → 限制为0.5 | 0.50 | 极强（已限制） |

### 5.4 k 值的用途

系数 k 主要用于计算**上移/下移步长**：

```
上移步长 = k × ATR_smooth
下移步长 = k × ATR_smooth
```

具体应用见《网格参数计算公式》文档。

**逻辑解释**：
- ADX 越高，趋势越强 → k 越大 → 步长越大 → 移动更积极
- ADX 接近25（刚进入趋势）→ k 接近0 → 步长很小 → 保守移动
- 趋势极强时（ADX≥40）→ k=0.5（上限）→ 但此时应暂停网格而非移动

## 6. 完整算法流程

### 6.1 主流程伪代码

```python
class MarketStateDetector:
    def __init__(self):
        self.prev_state = "震荡"
        self.state_confirm = StateConfirmation(confirm_count=3)
    
    def detect(self, klines_15m, klines_1h, klines_4h):
        """
        主入口：检测市场状态
        
        参数:
            klines_15m: 15分钟K线数据
            klines_1h:  1小时K线数据
            klines_4h:  4小时K线数据
        
        返回:
            {
                "final_state": "震荡" | "上升趋势" | "下降趋势" | "强趋势暂停",
                "adx_1h": ADX值,
                "atr_smooth": 平滑ATR值,
                "k": 趋势强度系数,
                "ema_fast_1h": EMA(20),
                "ema_slow_1h": EMA(50),
                "ema_fast_4h": EMA(20),
                "ema_slow_4h": EMA(50),
                "adx_4h": ADX值
            }
        """
        # 第1步：计算1小时周期指标
        adx_1h = calculate_adx(klines_1h, period=14)
        ema_fast_1h = calculate_ema(klines_1h, period=20)
        ema_slow_1h = calculate_ema(klines_1h, period=50)
        atr_1h = calculate_atr(klines_1h, period=14)
        atr_smooth = calculate_ema_of_atr(atr_1h, period=14)
        
        # 第2步：计算4小时周期指标
        adx_4h = calculate_adx(klines_4h, period=14)
        ema_fast_4h = calculate_ema(klines_4h, period=20)
        ema_slow_4h = calculate_ema(klines_4h, period=50)
        
        # 第3步：15分钟价格（用于边界检测）
        current_price = klines_15m[-1]["close"]
        
        # 第4步：判定1小时状态
        state_1h = self._single_tf_state(adx_1h, ema_fast_1h, ema_slow_1h)
        
        # 第5步：判定4小时状态
        state_4h = self._single_tf_state(adx_4h, ema_fast_4h, ema_slow_4h)
        
        # 第6步：多时间框架交叉确认
        final_state = self._multi_tf_confirm(state_1h, state_4h)
        
        # 第7步：状态确认机制
        self.state_confirm.update(final_state)
        
        # 检查是否有极端情况需要立即生效
        if self._is_extreme_case(adx_4h, atr_smooth):
            confirmed_state = final_state
        else:
            confirmed_state = self.state_confirm.get_confirmed_state()
            if confirmed_state is None:
                confirmed_state = self.prev_state  # 未确认则保持前一状态
        
        # 第8步：计算趋势强度系数 k
        if confirmed_state in ["上升趋势", "下降趋势"]:
            k = min(0.5, max(0, (adx_1h - 25) / 30))
        else:
            k = 0
        
        # 第9步：更新前一状态
        self.prev_state = confirmed_state
        
        return {
            "final_state": confirmed_state,
            "adx_1h": adx_1h,
            "atr_smooth": atr_smooth,
            "k": k,
            "ema_fast_1h": ema_fast_1h,
            "ema_slow_1h": ema_slow_1h,
            "ema_fast_4h": ema_fast_4h,
            "ema_slow_4h": ema_slow_4h,
            "adx_4h": adx_4h,
            "current_price": current_price
        }
    
    def _single_tf_state(self, adx, ema_fast, ema_slow):
        """单时间框架状态判定"""
        if adx >= 40:
            return "强趋势"
        elif adx < 20:
            return "震荡"
        elif adx >= 25:
            if ema_fast > ema_slow:
                return "上升趋势"
            else:
                return "下降趋势"
        else:
            return "震荡"  # 灰色区域保守处理
    
    def _multi_tf_confirm(self, state_1h, state_4h):
        """多时间框架交叉确认"""
        # 4小时强趋势 → 强制暂停
        if state_4h == "强趋势":
            return "强趋势暂停"
        
        # 1小时震荡 → 最终震荡
        if state_1h == "震荡":
            return "震荡"
        
        # 1小时强趋势 → 暂停
        if state_1h == "强趋势":
            return "强趋势暂停"
        
        # 1小时上升趋势
        if state_1h == "上升趋势":
            if state_4h == "上升趋势":
                return "上升趋势"
            else:
                return "震荡"  # 降级
        
        # 1小时下降趋势
        if state_1h == "下降趋势":
            if state_4h == "下降趋势":
                return "下降趋势"
            else:
                return "震荡"  # 降级
        
        return "震荡"
    
    def _is_extreme_case(self, adx_4h, atr_smooth):
        """检查是否为极端情况"""
        # 4小时ADX≥40，立即暂停
        if adx_4h >= 40:
            return True
        # 其他极端情况可由外部传入价格偏离等信息判断
        return False
```

### 6.2 数据需求

| 数据类型 | 所需K线数量 | 说明 |
|----------|------------|------|
| 15分钟K线 | 至少20根 | 获取最新标记价格 |
| 1小时K线 | 至少100根 | 计算ADX需要至少14根，建议更多保证精度 |
| 4小时K线 | 至少100根 | 同上 |

### 6.3 计算周期

| 计算任务 | 执行频率 | 说明 |
|----------|---------|------|
| 获取15分钟K线 | 每15分钟 | 可简化为每小时 |
| 获取1小时K线 | 每小时整点后 | 确保K线已收盘 |
| 获取4小时K线 | 每小时 | 取最新的4hK线 |
| 计算技术指标 | 每小时 | 与数据获取同步 |
| 状态判定 | 每小时 | 计算完成后执行 |

## 7. 边界条件与异常处理

### 7.1 数据不足处理

| 场景 | 处理方式 |
|------|---------|
| 1小时K线不足14根 | 使用已有数据计算，但标记为"数据不足，结果不可靠" |
| 4小时K线不足14根 | 暂时忽略4小时过滤，仅使用1小时判定 |
| 15分钟K线获取失败 | 使用最近一次已知价格 |

### 7.2 指标异常值处理

| 场景 | 处理方式 |
|------|---------|
| ATR 为 0 或极小值 | 使用最近10次ATR的平均值替代 |
| ADX > 100（理论上不可能） | 标记为数据异常，使用上一次有效值 |
| EMA 出现 NaN | 跳过本次计算，等待下一轮 |

### 7.3 网络异常处理

| 场景 | 处理方式 |
|------|---------|
| API 连续报错或延迟 > 3秒 | 触发紧急暂停协议 |
| 网络断开 | 取消所有挂单，保持持仓，发送警报 |

### 7.4 状态频繁切换防护

| 防护机制 | 参数 | 效果 |
|----------|------|------|
| 连续确认 | 3次 | 3小时内未确认则不切换 |
| 灰色区域保守 | ADX在20~25之间 | 保持前一状态 |
| 极端情况快通道 | 价格偏离>10%或ATR变化>50% | 跳过确认立即调整 |
