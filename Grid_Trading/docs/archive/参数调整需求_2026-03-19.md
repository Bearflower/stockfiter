我是想你的交易系统会针对我现有的网格订单进行调整吧。我告诉你有哪些参数可以调整：网格交易价格范围、网格数量、停止上移价格、停止下移价格、网格终止最低价格、网格终止最高价格。以下是详细的计算过程：

1. 网格交易价格范围（上边界 / 下边界）
项目	说明
修改逻辑	需终止重建：调用币安终止网格API → 等待平仓完成 → 用新参数调用创建网格API
计算逻辑	根据市场状态和波动率动态计算新边界
计算公式：

text
ATR_smooth = EMA(ATR(14), 14)   # 平滑ATR
基准宽度 = 4 × ATR_smooth
中心价格 = 当前标记价格

if 市场状态 == 震荡:
    下边界 = 中心价格 - 基准宽度 / 2
    上边界 = 中心价格 + 基准宽度 / 2
elif 市场状态 == 上升趋势:
    下边界 = 中心价格 - 1.5 × ATR_smooth   # 浅下界
    上边界 = 中心价格 + 4 × ATR_smooth      # 深上界
elif 市场状态 == 下降趋势:
    下边界 = 中心价格 - 4 × ATR_smooth      # 深下界
    上边界 = 中心价格 + 1.5 × ATR_smooth    # 浅上界
边界保护：

确保 上边界 > 下边界 + 最小宽度（最小宽度建议 2×ATR_smooth）

不得超出历史极端价格（可选）

触发条件：

平滑ATR变化超过 ±20%（相对于上次调整时的值）

市场状态发生变化（震荡↔趋势）

价格已运行到当前网格边缘附近（例如价格距上边界 < 0.5×ATR_smooth）

2. 网格数量
项目	说明
修改逻辑	需终止重建（与价格范围修改同步进行）
计算逻辑	根据波动率自适应调整网格密度
计算公式：

text
基准网格数 = 30   (可配置)
基准ATR = 过去90天ATR的均值（或指数加权移动平均）
当前ATR_smooth = 同上

网格数量 = 基准网格数 × (基准ATR / 当前ATR_smooth)
网格数量 = max(20, min(50, 网格数量))   # 限制在20~50之间
逻辑解释：

波动率升高（当前ATR变大） → 网格数量减少 → 格子变宽，减少被套仓位

波动率降低 → 网格数量增加 → 格子变密，增加获利机会

触发条件：

平滑ATR变化超过 ±20%（可与价格范围调整同步，避免频繁终止重建）

3. 停止上移价格
项目	说明
修改逻辑	可直接修改：调用币安修改网格API（更新停止上移价格字段）
计算逻辑	在上升趋势中，根据价格突破和趋势强度动态上移
计算公式：

text
趋势强度系数 k_trend = min(0.5, max(0, (ADX - 25) / 30))   # ADX越高，系数越大
上移步长 = k_trend × ATR_smooth

新停止上移价格 = max(当前网格上边界 + 上移步长, 上一次的停止上移价格)
触发条件（满足任意一条即可）：

价格连续向上突破网格层数 ≥ 3层（在5分钟内）

ADX > 25（确认有上升趋势）

当前价格已超过当前的停止上移价格

注意：

每次上移后，应将“上一次的停止上移价格”更新为新值

修改后需保存到本地状态

4. 停止下移价格
项目	说明
修改逻辑	可直接修改：调用币安修改网格API（更新停止下移价格字段）
计算逻辑	在下降趋势中，根据价格跌破和趋势强度动态下移
计算公式：

text
趋势强度系数 k_trend = min(0.5, max(0, (ADX - 25) / 30))
下移步长 = k_trend × ATR_smooth

新停止下移价格 = min(当前网格下边界 - 下移步长, 上一次的停止下移价格)
触发条件（满足任意一条即可）：

价格连续向下突破网格层数 ≥ 3层（在5分钟内）

ADX > 25（确认有下降趋势）

当前价格已低于当前的停止下移价格

注意：

下移步长同样基于趋势强度

修改后更新本地记录

5. 网格终止最低价格（硬止损线）
项目	说明
修改逻辑	可直接修改：调用币安修改网格API（更新终止最低价格字段）
计算逻辑	根据市场状态和盈利情况动态调整，但保守调整，仅在盈利时考虑上移
计算公式：

text
基础终止最低价格 = 初始网格下边界 - 2 × ATR_smooth   # 创建网格时设定
当前盈利状态：total_PnL_percent（总盈亏百分比）

if total_PnL_percent > 0:   # 盈利状态下可考虑上移止损
    新终止最低价格 = max(当前终止最低价格, 当前价格 - 3 × ATR_smooth)
else:   # 亏损或保本状态，维持原值或不变（不建议在亏损时移动止损线）
    新终止最低价格 = 当前终止最低价格   # 或保持不变
触发条件：

盈利状态下，价格持续上涨，且当前价格已远离原止损线（例如价格 > 原终止最低价格 + 2×ATR）

为避免频繁修改，可设置最小调整间隔（例如每4小时最多调整一次）

注意：

终止最低价格是最后的防线，上移时应保守（如用3倍ATR作为缓冲）

亏损时绝不向下移动止损线（避免死扛扩大亏损）

6. 网格终止最高价格（硬止盈线）
项目	说明
修改逻辑	可直接修改：调用币安修改网格API（更新终止最高价格字段）
计算逻辑	结合移动止盈机制动态调整
计算公式：

text
基础终止最高价格 = 初始网格上边界 + 2 × ATR_smooth   # 创建网格时设定
移动止盈启动阈值 = 15%   # 总盈利百分比
回撤保护距离 = 0.5 × (最高盈利时的价格 - 当前价格)   # 回撤一半时触发

if total_PnL_percent > 移动止盈启动阈值:
    # 记录本次盈利周期内的最高价 peak_price
    # 当价格从 peak_price 回落时，计算回撤比例
    新终止最高价格 = min(当前终止最高价格, peak_price - 回撤保护距离)
else:
    新终止最高价格 = 当前终止最高价格   # 未启动移动止盈前保持不变
触发条件：

总盈利首次超过15%（启动移动止盈模式）

在移动止盈模式下，价格从最高点回落，且回撤幅度达到一定阈值（例如回撤到最高价的95%以下）

为简化，可在每次巡检时重新计算，若新值低于旧值则更新

注意：

终止最高价格通常只下移（降低止盈门槛）来锁定利润

如果价格继续创新高，可保留原值，等待回落

附：市场状态判断逻辑（供计算时使用）
text
ADX = ADX(14)
EMA_fast = EMA(20)
EMA_slow = EMA(50)

if ADX < 20:
    状态 = "震荡"
elif ADX > 25:
    if EMA_fast > EMA_slow:
        状态 = "上升趋势"
    else:
        状态 = "下降趋势"
else:   # 20 ≤ ADX ≤ 25
    # 保持前一状态，或根据ADX变化趋势判断
    状态 = 前一状态   # 简单处理：不切换
多时间框架确认（可选）：

同时检查4H周期的ADX和EMA，与1H结果一致时才确认状态改变。

实现要点总结
参数存储：程序需维护当前网格的所有参数（包括可修改的6项），每次巡检时计算新值，并与当前值比较。

触发条件：设定合理的阈值和最小调整间隔，避免过于频繁的修改（尤其终止重建）。

API调用：

终止重建：POST /fapi/v1/grid/stop → 等待订单完成 → POST /fapi/v1/grid/create

修改停止/终止价格：POST /fapi/v1/grid/update （具体接口名需查阅币安文档，可能为modify）

平滑处理：使用指数移动平均平滑ATR，避免异常跳动影响。

安全边界：所有计算出的价格应进行合理性校验，防止出现下边界高于上边界等错误。
