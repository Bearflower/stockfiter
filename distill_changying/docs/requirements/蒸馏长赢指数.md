“蒸馏”一个博主的本质，就是**把他的海量内容压缩成一套结构清晰、可快速调用的认知资产**——可能是他的核心观点、思维框架、金句、知识图谱，甚至是你将来写作、决策时的灵感来源。

你已有原始 Markdown 文件并放在 Obsidian 里，这是最好的起点。接下来不需要“一个技能”解决所有问题，而是一个**组合拳**，从粗到细层层提炼。下面是从易到难、可直接落地的方案。

---

### 一、先在 Obsidian 内部建立“提炼结构”
这一步不依赖外部工具，用插件把散落的笔记串成网络。

#### 1. 搭建内容地图（MOC）
为这位博主创建一张总索引笔记 `博主名 MOC`，用于汇聚所有提炼成果。
- 手动或通过 **Dataview** 插件，列出全部博文、按时间/标签分组。
- 示例 Dataview 查询：`LIST FROM #博主名 SORT file.ctime DESC`  
  这样你一眼就能看到他的写作演变轨迹。

#### 2. 用标签和元数据做粗分类
在每篇博文的 frontmatter 中加入：
```yaml
---
tags: [观点, 方法论, 案例]
topic: 个人成长/投资/技术
key_point: "核心一句话"
---
```
之后就能用 Dataview 聚合，比如“他关于投资的文章共 23 篇，核心观点分别是什么”。

#### 3. 用渐进式总结法手动精炼
对每篇博文，执行**层叠笔记**：
- **第 1 层**：原文（你已有）
- **第 2 层**：粗摘要（用 `> [!summary]` 块写下 3-5 句话）
- **第 3 层**：一句话核心观点
- **第 4 层**：提炼成他自己的“思维模型卡片”（用 `> [!model]` 记录）

Obsidian 的**块引用**和**嵌入**（`![[笔记名#段落]]`）能让你随时把高浓度观点拼成新文章，而不用重复复制。

---

### 二、引入 AI 做批量深度提炼（最推荐，效率翻倍）
这是“蒸馏”的关键杠杆。Markdown 文件天然适合喂给大语言模型。

#### 1. 批量生成摘要与关键词
用脚本或现成工具（如 **Obsidian Smart Connections**、**Text Generator** 插件，或直接调用 GPT API），遍历所有博文文件，为每篇生成：
- 一句话核心观点
- 3 个关键词
- 一篇 100 字摘要
然后把这些写回 frontmatter 或文首，再用 Dataview 聚合，瞬间拥有“博主的观点数据库”。

#### 2. 跨文章提取思维框架
将全部博文摘要合并成一个长 Prompt，让 AI 做：
- **主题聚类**：他主要讨论了哪几个核心命题？每个命题下的标志性观点是什么？
- **常用思维模型**：他反复使用的分析框架（如“第一性原理”“系统思考”）。
- **论证结构**：他讲道理的典型路径是什么。
- **价值观线索**：从字里行间提取他看重什么、反对什么。

你会得到一张“博主思想地图”，直接放进你的 MOC。

#### 3. 生成人格化输出
- **金句库**：让 AI 从文中挑出最具传播力的句子，按主题分类。
- **风格模仿**：提炼他的语言习惯、比喻偏好、句式节奏，形成一份“写作风格指南”，方便你以后用他的口吻写作。
- **假设性问答**：问他如果面对某个新问题，根据历史文章，他会怎么回答。这能检验你对他的理解深度。

### 三、可视化与分析（进阶玩家）
如果你愿意动一点代码，能让提炼更量化。

#### 1. 用 Python 做文本分析
- 关键词提取（TF-IDF）、主题建模（LDA）来发现他无意识反复强调的词群。
- 情感极性变化：他这些年观点是越来越乐观还是悲观？
- 引用网络：他喜欢引用哪些书、哪些人？这些可以独立成笔记，形成“影响源”图谱。

#### 2. 在 Obsidian 中可视化
- **Excalidraw** 手绘他的思想节点图。
- **Juggl** 或 **Graph Analysis** 插件查看所有笔记间的链接，发现自然形成的知识簇。  
  当你手动给观点之间建立 `[[链接]]` 后，图谱会展示出他思想的内在结构，甚至可以找到他从未写明的“暗线”。

## 一、Obsidian 插件武器库（按蒸馏角色分类）

### 1. 聚合与索引：Dataview
**作用**：把分散的笔记变成动态数据库，是 MOC 的核心引擎。
- **安装后**：在任意笔记中插入代码块，实时列出、过滤、排序所有博文。
- **示例 MOC 页面** `博主名-HUB`：
  ````markdown
  ```dataview
  TABLE dateformat(file.ctime, "yyyy-MM-dd") AS 创建时间, key_point AS 核心观点, tags AS 标签
  FROM #博主名
  SORT file.ctime DESC
  ```
  ````
- **进阶**：等我们用脚本或插件注入 `summary` 和 `keywords` 到 frontmatter 后，可直接在表格中显示摘要，一眼扫完他的思想脉络。

### 2. AI 内容生成：Text Generator
**作用**：直接在 Obsidian 内调用 GPT/Claude 等模型，批量生成摘要、关键词、翻译，甚至模仿文风。
- **配置**：在设置里填入你的 OpenAI / Claude API Key，选择模型。
- **核心用法——模板提炼**：
  创建一个模板 `提炼摘要.md`：
  ```
  ---
  Prompt: 请根据以下文章内容，生成一个不超过100字的中文摘要和3个关键词，以YAML格式输出。输出格式：
  summary: "摘要内容"
  keywords: [关键词1, 关键词2, 关键词3]
  ---
  {{content}}
  ```
  然后选中一篇博文全文，用命令 `Text Generator: Generate from template` 选择该模板，AI 会自动生成摘要和关键词。**要批量处理，可以配合 QuickAdd 的宏来遍历文件**（下文会提）。
- **一键注入 Frontmatter**：你也可以设计模板，直接输出包含 `---` 的完整 frontmatter，然后手动或脚本替换。

### 3. 语义连接与发现：Smart Connections
**作用**：基于本地 AI 嵌入，自动显示与你当前笔记最相似的其他笔记，发现隐藏联系。
- **无需 API Key**（使用本地模型），完全隐私。
- **用法**：打开一篇博文，右侧面板会列出语义最接近的几篇。点击即可跳转。这在提炼时能帮你：“原来这两篇看似无关的文章，底层都在讲系统论”。

### 4. 快速捕获与模板自动化：QuickAdd
**作用**：将复杂操作一键化。
- **设置宏**：可以结合 `Text Generator` 插件，创建一个“自动提炼当前文件”的宏：获取文件内容 → 调用模板生成摘要 → 将结果插入 frontmatter。具体操作涉及编写 QuickAdd 的“Capture”或“Macro”，有点门槛，但设置一次终身受益。

### 5. 结构可视化：Excalidraw & Juggl
- **Excalidraw**：手绘思想拓扑图。为博主的核心框架画出视觉模型，并嵌入双链，点击图形直接跳转到原文论证处。适合最终呈现“博主思想地图”。
- **Juggl**：超越原生图谱，可按主题、标签等自定义节点样式，用连线表达“反驳”“发展”“解释”等关系，非常适合把蒸馏出的思维模型之间的关系画成概念图。

### 6. 长篇写作与重组：Longform
- **作用**：将多篇零散笔记拼装成一篇长文。当你提炼出“博主投资观”的 20 张卡片后，可用 Longform 将它们排序、编排，导出为一篇完整的分析文章。

### 7. 拆分与原子化：Note Refactor
- **作用**：把一篇长博文中提取出来的单个观点、金句，直接拆成独立的卡片笔记。选中一段话，快捷键拆出，自动嵌入反向链接。是做“核心观点卡片盒”的神器。

## 二、Python 批量提炼脚本框架

如果你希望高效、精准地一次性为所有博文打上摘要和关键词，这个脚本最合适。它会遍历所有 Markdown 文件，调用 OpenAI API（可换成 Claude 或其他），并将结果安全写入 frontmatter。

### 准备工作
- 安装 Python 依赖：`pip install openai python-frontmatter`
- 准备 API Key，设置环境变量 `export OPENAI_API_KEY="sk-..."`

### 完整脚本 `distill_blogger.py`
```python
import os
import frontmatter
import openai
from time import sleep

# 配置项
VAULT_PATH = "/Users/yourname/Obsidian/博主仓库"  # 改为你的路径
MODEL = "gpt-4o-mini"          # 性价比高，或 gpt-4o
BATCH_SIZE = 5                 # 每处理5篇暂停一下，避免限流
DELAY = 2                      # 每篇文章间延时(秒)

openai.api_key = os.getenv("OPENAI_API_KEY")

def get_summary_and_keywords(text):
    """调用AI返回摘要和关键词"""
    prompt = f"""请仔细阅读以下博文，完成两项任务：
1. 用一句不超过100字的中文概括其核心观点。
2. 提取3-5个最能代表本文主题的关键词。
请严格按以下JSON格式输出，不要包含任何其他文字：
{{"summary": "...", "keywords": ["...", "..."]}}

博文内容：
{text[:3000]}"""  # 如果文章很长，可截断或做分块，这里限制输入长度

    response = openai.ChatCompletion.create(
        model=MODEL,
        messages=[{"role": "user", "content": prompt}],
        temperature=0.3,
    )
    return response.choices[0].message.content

def process_markdown_file(filepath):
    """读取、提炼并写回单个md文件"""
    post = frontmatter.load(filepath)
    content = post.content
    if not content.strip():
        return False

    # 如果已经有summary和keywords，可选择跳过，避免重复消耗API
    if 'summary' in post and 'keywords' in post:
        print(f"跳过已提炼: {filepath}")
        return False

    try:
        result_str = get_summary_and_keywords(content)
        # 解析AI返回的JSON
        import json
        # 清理可能存在的Markdown代码块符号
        clean_str = result_str.replace('```json', '').replace('```', '').strip()
        result = json.loads(clean_str)

        # 写入frontmatter
        post['summary'] = result['summary']
        post['keywords'] = result['keywords']
        post['source'] = 'ai-distilled'  # 标记，方便管理

        frontmatter.dump(post, filepath)
        print(f"已提炼: {filepath}")
        return True
    except Exception as e:
        print(f"处理失败 {filepath}: {e}")
        return False

def main():
    md_files = []
    for root, dirs, files in os.walk(VAULT_PATH):
        for file in files:
            if file.endswith('.md'):
                md_files.append(os.path.join(root, file))

    print(f"发现 {len(md_files)} 个Markdown文件")
    processed = 0
    for i, filepath in enumerate(md_files, 1):
        if process_markdown_file(filepath):
            processed += 1
        sleep(DELAY)  # 礼貌调用
        if i % BATCH_SIZE == 0:
            print(f"已完成 {i}/{len(md_files)}，暂停5秒...")
            sleep(5)

    print(f"处理完毕，成功为 {processed} 篇文章注入摘要。")

if __name__ == "__main__":
    main()
```

**使用说明**：
- 先在一两个文件上测试，确认 frontmatter 正确注入。
- 如果文章过长，超过 Token 限制，可以在 `text[:3000]` 处做截断，或使用 `tiktoken` 精确切分。
- 脚本写入了 `source: ai-distilled`，方便以后区分哪些是 AI 注入的，也可用 Dataview 筛选 `WHERE source = "ai-distilled"`。

## 三、终极跨文章提炼 Prompt 模板

在所有博文都有了 `summary` 后，你可以用 Dataview 把全部摘要汇集成一个表格，复制出来，粘贴到 ChatGPT/Claude 的对话框中，然后发送下面这个精心设计的 Prompt。它会为你生成博主完整的认知资产清单。

### 步骤
1. 在 Obsidian 新建笔记，插入：
   ````markdown
   ```dataview
   TABLE summary AS "核心观点", keywords AS "关键词"
   FROM #博主名
   WHERE summary
   ```
   ````
2. 复制渲染后的表格（纯文本），作为 “【所有文章摘要】” 内容。
3. 发送如下 Prompt：

```
你是一位顶级知识管理专家和认知科学家。我需要你帮我深度萃取一位博主的全部思想。

以下是他的全部文章摘要，格式为：| 核心观点 | 关键词 |

【所有文章摘要】
（此处粘贴 Dataview 表格的内容）

请完成以下任务，并以结构化 Markdown 输出，便于我直接保存为永久笔记：

1.  **核心命题聚类**：将他讨论的所有话题归类为 5-8 个核心命题，并为每个命题写一段 50 字的描述。
2.  **十大核心观点**：提炼出他最核心、最反复强调的 10 个观点。每个观点需包含：
    - 观点陈述
    - 一句最具代表性的原文片段（从摘要中推断典型表述）
    - 出现频次估计（高/中/低）
3.  **思维模型工具箱**：识别他文章里隐含或明确使用的思维模型（如第一性原理、复利思维、系统思考等），列出 5-10 个，并简要说明他如何运用。
4.  **价值观罗盘**：从字里行间提取他珍视什么、反对什么，列成简洁的清单。
5.  **演化轨迹**：如果文章有时间跨度，请猜测他这些年观点或关注点可能发生了怎样的变化（用“早期… 近期…”句式，如无法推断则跳过）。
6.  **影响源推测**：根据关键词和观点，推测他可能受到哪些书籍、人物或思想流派的影响。
7.  **矛盾与张力**：有没有哪些观点之间存在潜在矛盾或未解决的张力？请指出来，这往往是思想最有趣的地方。

请确保输出格式精美，使用标题、列表和引用，我可以一键存入 Obsidian 作为“博主思想矿脉”总索引。
```

将 AI 的回复保存为 `博主思想矿脉.md`，用 `[[ ]]` 链接到你感兴趣的原文卡片，这座知识富矿就真正属于你了。

## 四、整合工作流（一步一图）

1. **准备**：所有博文在一个文件夹，打上统一标签（如 `#博主名`）。
2. **打标**：运行 Python 脚本（或使用 Text Generator 手动），为每篇文章注入 `summary` 和 `keywords`。
3. **建索引**：创建 MOC 笔记，用 Dataview 把所有文章摘要展示出来，作为动态总览。
4. **深萃取**：将摘要汇总，用上述终极 Prompt 生成“博主思想矿脉”。
5. **卡片化**：阅读矿脉笔记，用 Note Refactor 把每一个核心观点拆成独立卡片，用双链关联到原文。
6. **绘图**：打开 Excalidraw，拖入核心思维模型卡片，画出它们之间的关系图，永久挂在侧边栏。
7. **复盘**：日常浏览时，Smart Connections 自动浮现未标注的关联，不断丰富你的理解。

## 核心思路：从“查资料”到“问智囊”
不要把这些笔记当作死文档，而是当作**一个可以对话的智囊团**。你随时向他提问，而他用你提炼出的框架来回答。

### 场景一：写作加速器 —— 让你下笔时“有人撑腰”

**1. 论证时有据可依**
当你要写一篇“关于长期主义”的文章时：
- 打开你的 **核心观点卡片盒**，找到“长期主义”卡片，里面可能有他的一句话、一个案例。
- 用 Obsidian 的 `[[ ]]` 直接嵌入到文章里，瞬间拥有深度引用。
- **操作**：搜索 `[topic:长期主义]` （如果你在frontmatter里设了topic），Dataview列出所有相关观点，挑一个最锋利的。

**2. 金句注入灵魂**
在文章每个段落结尾，需要一句点睛之笔时：
- 打开 **金句库**（按主题分类好的），复制粘贴。
- 比如写到“耐心”时，直接调用他写的“耐心不是等待，而是复利在时间里发酵时的姿态”。

**3. 风格模仿**
当你需要以一种特定口吻写东西时：
- 调出 **写作风格画像** 笔记，里面有他的比喻偏好（如总用园艺、航海比喻）、句式节奏（短句多、反问多）。
- 配合 **Text Generator** 插件，把风格画像作为Prompt前缀，输入你想表达的大意，AI 直接生成他的语气。比如：
  > `用[博主名]的风格写一段关于面对不确定性的建议：……`

### 场景二：决策参考 —— 让他帮你分析问题

## 一、先理解三种方式的本质，避免选错

| 方式 | 最适合什么环节 | 致命短板 |
|------|----------------|----------|
| **Skill / 流程包** （比如 Obsidian 模板 + QuickAdd 宏） | 固化重复的**分析流程**，确保你每次按博主框架思考，不遗漏步骤 | 无法处理动态数据，不能自动获取行情、财务数据 |

## 二、博主的投研方法，如何拆解成可执行单元？

## 五、为什么不是纯代码或纯智能体？

- **纯代码**：你可以把筛选规则写成代码，但遇到“这个管理层是否诚信”这样的问题，代码完全无能为力。博主大量的智慧在于定性判断。
- **纯智能体**：智能体能高谈阔论，但如果你问它“现在A股所有满足XX苛刻财务指标的公司有哪些”，它可能一本正经地胡说八道，因为它没有实时数据库。代码才是精确的过滤器。
- **单一大而全的智能体**：把所有知识塞给一个智能体，它会混淆角色，分析时难以自己批判自己。多个角色独立运作，形成**对抗协作**，质量远高于一个“全能神”。
