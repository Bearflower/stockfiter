## 方案概览

这个项目按照 `蒸馏长赢指数.md` 的方法论，将 283 篇博客内容蒸馏为认知资产。核心思路是**两层蒸馏 + CLI 工具**：

### 第一层蒸馏（`summarize`）
- Python 脚本逐篇调用 LLM API，为每篇博客生成：
  - 一句话核心观点（≤100字）
  - 3-5 个关键词
  - 主题分类
- 结果汇总为 `docs/distilled/blog-index.csv`
- 支持断点续跑、年份筛选、速率控制

### 第二层蒸馏（`analyze`）
- 将所有摘要汇总后，一次性发送给 LLM 做跨文章深度分析
- 生成报告包含：核心命题聚类、十大核心观点、思维模型工具箱、价值观罗盘、演化轨迹、矛盾与张力

### 产物输出
```
docs/distilled/
├── README.md          # 索引入口
├── blog-index.csv     # 283篇文章的摘要索引表
├── 核心观点矿脉.md     # 跨文章深度分析报告
└── 金句库.md          # 按主题分类的金句
```

### 关键设计决策
- **不修改原始文件**：所有产物输出到独立目录
- **配置文件驱动**：API Key、模型、速率限制等全部通过 `config.yaml` 管理
- **先做最小闭环**：3-5 篇端到端测试 → 确认效果后再批量跑全量

### 各模块功能概要

**`config.yaml`** -- 完整的 YAML 配置文件，包含 api、rate_limit、paths、truncation、deep_analysis 五个配置节，所有参数均可通过此文件调节。

## 各模块核心功能概要

### `file_handler.py`
- **`list_blog_files`**: 遍历 283 篇 `.md` 文件，支持 `year` 和 `pattern` 筛选
- **`read_blog`**: 读取文件内容，自动去除 YAML frontmatter，编码错误用 `errors='replace'` 处理
- **`get_blog_identifier`**: 基于文件名 MD5 前 8 位生成唯一标识

### `summarizer.py`
- **`summarize_article`**: 调用 OpenAI API（兼容 `base_url`），内容超 `max_chars` 自动截断并警告
- **`summarize_with_retry`**: 指数退避重试（429/超时等），JSON 解析失败不重试直接返回错误标记

### `state_manager.py`
- **`load_state` / `save_state`**: JSON 持久化，`save_state` 使用原子写入（`.tmp` + `os.replace`）
- **`is_processed` / `mark_processed`**: 检查/标记处理状态，自动记录 UTC 时间戳

### `batch_processor.py`
- **`run_summarize`**: 编排完整流程：文件遍历 -> 状态加载 -> 跳过已处理 -> 速率控制 -> 逐篇 LLM 调用 -> 每篇即时保存状态
- **`export_to_csv`**: 导出 `blog-index.csv`（UTF-8 BOM，Excel 友好），路径自动确保存在

## update 子命令 -- 增量知识库更新

### 概述

当 `docs/blog/` 目录下有新增的博客文件时，无需重新跑全量蒸馏（`distill`），可以使用 `update` 子命令仅处理新增内容。

`update` 命令的核心逻辑：
1. 扫描 `docs/blog/` 获取全部博客文件列表
2. 加载 `docs/distilled/.state.json` 获取已处理状态
3. 比对得出新文件（文件标识符不在 state 中的文件）
4. 仅对新增文件执行第一层蒸馏（摘要+关键词）
5. 如有新文件或 `--force-analyze`，重新执行全量跨文章深度分析
6. 更新 `blog-index.csv`
7. 重新生成「核心观点矿脉.md」、「金句库.md」、「README.md」
8. 生成/刷新 `.meta.yaml` 元数据文件

### 使用方式

```bash
cd /Users/yl/vscode/stockfilter_v3/distill_changying

# 增量更新（仅处理新增文件）
DEEPSEEK_API_KEY="sk-..." PYTHONPATH=. python3 scripts/distill/main.py update

# 增量更新 + 强制重新执行全量跨文章分析
DEEPSEEK_API_KEY="sk-..." PYTHONPATH=. python3 scripts/distill/main.py update --force-analyze
```

### 参数说明

| 参数 | 说明 |
|------|------|
| `--force-analyze` | 即使没有新文件也强制重新执行全量跨文章深度分析 |

### 注意事项

- 如果知识库已是最新（无新增文件），`update` 仅刷新 `.meta.yaml` 文件，不执行摘要和分析
- `update` 不会重新处理已有的旧文件，如需强制重新处理全部文件请使用 `distill --force`

## 调度器自动检测知识库更新机制

### 概述

`scripts/advisor/scheduler.py` 是 E大估值策略的调度器，每天 `23:10`（北京时间）执行估值扫描并推送到飞书。在推送完成后，调度器会**串行**检测知识库是否需要更新。

### 检测流程

```
run_scan_and_push() 完成后
    │
    ▼
run_knowledge_base_check()
    │
    ├─ 1. 检查当日是否已执行过更新（防止重复）
    │
    ├─ 2. 扫描 docs/blog/ 全部文件
    │
    ├─ 3. 加载 .state.json 获取已处理状态
    │
    ├─ 4. 比对得出新文件列表
    │
    ├─ 无新文件 → 记录日志，跳过
    │
    └─ 有新文件 → 执行增量蒸馏

         ├─ 生成 README.md
         └─ 生成 .meta.yaml
```

### 关键设计

- **同一天只检测一次**：通过 `last_kb_update_date` 变量防止重复触发

### 容错设计

- 观点提取失败不会阻塞蒸馏流程，仅输出警告日志
- 观点匹配失败时自动降级使用备用观点（从配置读取）
- 备用观点也存在默认值（内置两条经典观点），确保日报始终有"E大说过"段落

## 博客命名规范约定

### 存放位置

新增的博客文件需要放在 `docs/blog/` 目录下。

### 命名格式

文件名应包含日期信息，便于提取和排序。日期格式推荐以下两种：

**格式一：微博精选合集**
```
{年份}年{月份}月"ETF拯救世界"微博精选.md
```
示例：
- `2015年9-12月"ETF拯救世界"微博精选.md`
- `2021年09月"ETF拯救世界"微博精选.md`
- `2025年12月"ETF拯救世界"微博精选.md`

**格式二：发车计划文章**
```
{年份}年{月份}月长赢指数投资计划（{序号}）：{描述}.md
```
示例：
- `2025年12月长赢指数投资计划（一）：S买入一份.md`
- `2026年1月长赢指数投资计划（二）：150计划买入一份.md`
- `2023年8月长赢指数投资计划（四）：150_S计划各买入一份.md`

**格式三：历史兼容格式（周范围）**
```
{年份}【{MM}.{DD}-{MM}.{DD}】"ETF拯救世界"微博精选.md
```
示例：
- `2020【01.06-01.12】"ETF拯救世界"微博精选.md`

### 核心要求

- 文件名中**必须包含** "20xx年xx月" 或 "20xx-xx" 或 "20xx【" 格式的日期，日期信息用于 [metadata.py](file:///Users/yl/vscode/stockfilter_v3/distill_changying/scripts/distill/metadata.py) 中的 `extract_last_blog_date()` 函数提取最新博客日期
- 每月新增不超过 10 篇
- 手动放置到 `docs/blog/` 目录即可，调度器会自动检测新文件
- 文件名中尽量避免使用 `|`、`:`、`?`、`*` 等特殊字符，以保证跨平台兼容性
