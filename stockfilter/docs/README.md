基于 [vibe-coding-cn](https://github.com/tukuaiai/vibe-coding-cn) 项目的文档架构体系，提供标准化的文档组织、索引管理和知识沉淀能力。

**核心文档**:
- [📘 Vibe Coding 文档架构技能](Vibe_Coding%20文档架构技能.md) - 完整文档架构规范和最佳实践

**核心理念**:
- **文档即上下文**: 文档不是事后补充，而是开发的第一性要素
- **规划驱动**: 先结构后代码，规划好框架避免技术债
- **模块化组织**: 按职责分类，保持正交性
- **持续进化**: 文档随项目迭代而更新

**重构背景**: 项目经历了多个版本的迭代(V2.1, V2.2, V2.3, V2.4, V2.5),积累了大量历史代码和文档,导致项目结构臃肿、维护困难。为提高可维护性,于 2026-04-27 完成系统性重构。

**主要变更**:
- 创建统一回测器 `core/backtester.py`,支持多版本切换
- 创建统一配置文件 `config/config.yaml`,支持版本参数配置
- 创建主程序 `main.py`,支持定时任务和命令行模式
- 归档历史版本代码到 `archived/` 目录
- 优化项目结构,职责分明

## 📝 文档管理规范

### 文档分类原则

- **需求类 (requirements/)**: 项目业务需求、功能规格、版本迭代记录
- **报告类 (reports/)**: 项目阶段性报告、总结、分析、验证报告
- **部署类 (deployment/)**: 部署指南、操作手册、运维文档、使用手册
- **方案类 (schemes/)**: 策略配置方案、执行计划、实施方案
- **设计类 (designs/)**: 系统设计、技术架构、监控指南、规范文档

### 文档命名规范

- 使用中文命名，清晰表达文档内容
- 版本信息使用 `Vx.x` 格式
- 日期信息使用 `YYYYMMDD` 或 `YYYY-MM-DD` 格式
- 避免使用空格，使用下划线或连字符分隔

### 文档更新原则

1. **唯一性**: 同类文档保持最新版本，历史版本应归档或标注
2. **引用**: 在 README.md 中引用文档时应使用相对链接
3. **索引**: 新增文档应及时更新本索引文件
