# 配置管理设计 V3

## 1. 设计原则

1. **统一入口**：一个 `config.yaml` 管理所有配置
2. **环境隔离**：敏感信息通过环境变量注入（`${ENV_VAR}` 语法或独立 `.env` 文件）
3. **策略独立**：每个策略在 `strategies` 节下有独立的配置块
4. **定时调度独立**：`schedule` 节独立管理定时任务时间

## 3. 配置加载方式

### 3.1 main.py 中的加载

配置通过 [main.py](file:///Users/yl/vscode/stockfilter_v3/main.py) 中的 `load_config()` 函数直接使用 `yaml.safe_load()` 加载：

```python
def load_config(config_path: str = "config/config.yaml") -> dict:
    """加载配置文件"""
    if not os.path.exists(config_path):
        logger.warning(f"配置文件不存在: {config_path}，使用默认配置")
        return {}
    with open(config_path, 'r', encoding='utf-8') as f:
        return yaml.safe_load(f)
```

### 3.2 各模块读取配置

- **调度器**：`Scheduler.__init__(config)` -- 接受完整配置字典，从中读取 `global` 和 `strategies` 节
- **通知服务**：`NotificationService(config=config)` -- 读取 `global.notification` 节
- **策略初始化**：`OversoldBounceStrategy(params=ob_config.get('params', {}))` -- 从 `strategies.oversold_bounce.params` 读取
- **股票池过滤**：`filter_stock_list(df, config)` -- 接受 `global.stock_pool` 字典

> `global.stock_pool` 中的 `beijing_prefixes`、`new_third_board_prefixes`、`main_board_prefixes`、`exclude_index_keywords` 用于**覆盖** [data/database.py](file:///Users/yl/vscode/stockfilter_v3/data/database.py) 中 `filter_stock_pool` 的模块级默认值（`DEFAULT_BEIJING_PREFIXES` 等），配置缺失时回退到代码默认值。

### 3.3 没有 ConfigLoader 类

当前版本**没有** `ConfigLoader` 类，配置加载非常轻量：直接 `yaml.safe_load()` + 字典传递。环境变量注入通过 `os.getenv()` 在各个模块内部读取。

### 4.2 各模块的环境变量读取

- `DatabaseManager.__init__()` -- 读取 `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_SCHEMA`
- `FeishuNotifier.__init__()` -- 读取 `FEISHU_WEBHOOK`
- `utils/logger.py` -- 从 `config.yaml` 的 `global.logging` 节读取日志配置

## 5. 配置优先级

```
环境变量（os.getenv） > config.yaml（策略params节） > 代码默认值（_get_default_params()）
```

1. 数据库连接等基础设施通过 `os.getenv()` 读取环境变量
2. 策略参数从 `config.yaml` 的 `strategies.xxx.params` 读取，覆盖默认值
3. 策略默认参数在 `_get_default_params()` 方法中兜底

## 6. Docker 环境变量注入

```yaml
# docker-compose.yml 片段
services:
  stockfilter-v3-app:
    environment:
      - TZ=Asia/Shanghai
      - FEISHU_WEBHOOK=${FEISHU_WEBHOOK}
      - DB_PASSWORD=${DB_PASSWORD:?DB_PASSWORD must be set}
      - DB_HOST=${DB_HOST:-common_service_postgres}
      - DB_PORT=5432
      - DB_NAME=stockfilter
      - DB_USER=stockfilter_user
      - DB_SCHEMA=schema_stockfilter
```

> **R-14 语义**：`${DB_PASSWORD:?DB_PASSWORD must be set}` 表示 DB_PASSWORD 为**必填**，未配置（或为空）时 `docker compose up` 直接报错、生产容器启动失败——这是有意设置的失败前置检查，避免以空密码连上数据库。`.env.example` 中 `DB_PASSWORD=` 刻意留空，需由 CI/CD secrets 或手动 `export` 注入。

## 7. OBPC 策略 V2.1 新增配置参数说明

OBPC 策略 V2.1 在 V2.0 三层风控基础上新增市场状态识别增强功能，包括 MACD 动量过滤、均线斜率过滤、评分市场状态调整。所有新增参数位于 `strategies.oversold_bounce.params` 节下，均有默认值，确保 V2.0 配置文件可正常运行（向后兼容）。

### 7.1 index_filter 区块（V2.1 新增参数）

V2.1 在 `index_filter` 区块新增以下参数，用于市场状态识别增强：

| 参数 | 类型 | 默认值 | 取值范围 | 说明 |
|------|------|--------|---------|------|
| `method` | str | `'ma_position'` | `'ma_position'` / `'macd'` | 大盘趋势过滤方法。`ma_position` 为 V2.0 均线位置过滤（价格 vs 均线），`macd` 为 V2.1 动量过滤（DIF 方向）。两者互斥 |
| `macd_fast` | int | 12 | 正整数 | MACD 快线周期（EMA12），仅 `method: 'macd'` 时生效 |
| `macd_slow` | int | 26 | 正整数 | MACD 慢线周期（EMA26），仅 `method: 'macd'` 时生效 |
| `macd_signal` | int | 9 | 正整数 | MACD 信号线周期（DIF 的 9 日 EMA），仅 `method: 'macd'` 时生效 |
| `condition` | str | `'dif > 0'` | `'dif > 0'` | MACD 过滤条件，目前支持 `dif > 0`（DIF > 0 时放行），后续可扩展 `dif > dea`（金叉）等条件 |
| `slope_filter_enabled` | bool | false | true / false | 均线斜率过滤开关。默认关闭，启用后判断均线方向（向上/走平/向下） |
| `slope_ma_period` | int | 60 | 20 / 60 | 斜率计算的均线周期。可选 MA20 或 MA60，MA20 灵敏度高，MA60 稳定性强 |
| `slope_lookback` | int | 5 | 正整数 | 斜率回看天数（当前均线 vs N 天前均线）。值越小灵敏度越高，值越大稳定性越强 |
| `slope_threshold` | float | 0.002 | 正浮点数 | 斜率阈值（0.2%）。斜率大于该值才视为均线向上，否则视为向下。值越小过滤越宽松，值越大过滤越严格 |
| `min_index_data_days` | int | 30 | 正整数 | 最小指数数据获取天数。数据不足时跳过过滤并输出警告日志，不阻断扫描 |

**参数使用说明**：

1. **method 参数切换**：`method: 'ma_position'` 使用 V2.0 均线位置过滤，`method: 'macd'` 使用 V2.1 MACD 动量过滤，两者互斥不能同时启用。
2. **斜率过滤组合**：`slope_filter_enabled: true` 可与 `method: 'ma_position'` 或 `method: 'macd'` 组合使用，实现双重确认。
3. **数据不足处理**：当指数数据不足 `macd_slow + macd_signal`（默认 35 天）或 `slope_ma_period + slope_lookback`（默认 65 天）时，跳过对应过滤并输出警告日志。
4. **命中统计**：MACD 过滤命中计入 `skipped_macd_filter`，斜率过滤命中计入 `skipped_slope_filter`，便于回测分析。

### 7.2 score_adjustment 区块（V2.1 新增整段）

V2.1 新增 `score_adjustment` 区块，用于评分市场状态调整。在个股形态评分基础上加入"大盘相对强度"作为加分/减分项，使个股评分能反映大盘环境的影响。

| 参数 | 类型 | 默认值 | 取值范围 | 说明 |
|------|------|--------|---------|------|
| `enabled` | bool | false | true / false | 评分市场状态调整开关。默认关闭，启用后根据大盘环境调整个股评分 |
| `score_multiplier_strong` | float | 1.2 | 正浮点数 | 强势市场评分放大系数。大盘收盘价 ≥ MA20 且 MA20 斜率 > 0 时生效 |
| `score_multiplier_weak` | float | 0.8 | 正浮点数 | 弱势市场评分缩小系数。大盘收盘价 < MA20 或 MA20 斜率 ≤ 0 时生效 |
| `score_multiplier_extreme_weak` | float | 0.0 | 非负浮点数 | 极弱市场评分系数。大盘收盘价 < MA60 且 MA60 斜率 ≤ 0 时生效，0 = 评分归零 |
| `score_max_limit` | float | 100.0 | 正浮点数 | 评分调整后上限。调整后评分超过该值时截断 |
| `score_min_limit` | float | 0.0 | 非负浮点数 | 评分调整后下限。调整后评分低于该值时截断 |

**参数使用说明**：

1. **调整公式**：`adjusted_score = original_score × multiplier`，调整后评分限制在 `[score_min_limit, score_max_limit]` 区间内。
2. **市场状态判定**：
   - 强势市场：大盘收盘价 ≥ MA20 且 MA20 斜率 > 0，评分 × 1.2；
   - 弱势市场：大盘收盘价 < MA20 或 MA20 斜率 ≤ 0，评分 × 0.8；
   - 极弱市场：大盘收盘价 < MA60 且 MA60 斜率 ≤ 0，评分 × 0.0（归零）。
3. **与评分阈值过滤的关系**：评分调整在评分阈值判断前应用，调整后的评分用于 V2.0 评分阈值过滤判断。极弱市场评分归零等同于被评分阈值过滤。
4. **命中统计**：评分调整命中（系数 ≠ 1.0）计入 `skipped_score_adjustment`，日志中记录原始评分、调整系数、调整后评分。

### 7.3 V2.1 4 方案配置速查

V2.1 提供 4 个回测验证方案，通过配置文件的参数组合实现，无需修改代码即可切换：

| 方案 | method | slope_filter_enabled | slope_ma_period | long_ma_filter_enabled | score_adjustment.enabled | 过滤条件说明 |
|------|--------|---------------------|-----------------|----------------------|------------------------|---------|
| 方案1 | `macd` | `false` | - | - | `false` | 大盘 MACD DIF > 0 |
| 方案2 | `ma_position` | `true` | `20` | `false` | `false` | 大盘收盘价 > MA20 且 MA20 斜率 > 0 |
| 方案3 | `macd` | `true` | `20` | - | `false` | MACD + MA20 斜率（双重确认） |
| 方案4 | `ma_position` | `true` | `60` | `false` | `false` | 大盘 MA60 斜率 > 0 |

**回测方案切换**：通过命令行参数 `--scheme 1/2/3/4` 切换，自动覆盖配置文件中的对应参数，无需手动修改配置文件。

**推荐方案**：根据 V2.1 回测验证结果，推荐使用**方案2**（MA20 位置 + MA20 斜率 > 0），效果最好且配置简单。详见 [OBPC策略说明文档.md](./OBPC策略说明文档.md) 第 11 节"V2.1 回测验证结果"。

## 8. global.kline_update 数据完整性判定配置（2026-10-18 新增）

`scripts/data/update_kline_daily.py` 的 `UpdateResult.is_complete()` 方法读取此节配置，判定日更新数据是否达标。`scripts/verify_obpc_pipeline.py` 和 `scripts/monitor.sh` 也从此节读取阈值，**禁止硬编码**。

### 8.1 配置项一览

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `days_to_update` | int | 5 | C-1：更新最近多少天的数据（防止遗漏） |
| `request_timeout_seconds` | int | 15 | 单股抓取超时（秒） |
| `request_interval_seconds` | float | 0.05 | M-2：每次请求后休眠时间（秒），限流防止触发 Baostock API |
| `target_date_max_backtrack` | int | 7 | P1：计算目标交易日时最多回溯的自然日数（覆盖周末+常见节假日；春节例外时兜底到库内最新交易日） |
| `failure_rate_threshold` | float | 0.7 | 滑动窗口失败率熔断阈值 |
| `failure_window_size` | int | 100 | 滑动窗口大小（最近 N 次请求） |
| `failure_window_min_samples` | int | 50 | 熔断判定所需最小样本数 |
| `total_failure_limit` | int | 200 | 累计失败硬上限（单股 15s × 200 ≈ 3000s，在 3h 超时前熔断） |
| `min_success_rate` | float | 0.9 | 成功率红线：成功数 / (成功数 + 失败数)，低于此值判定为不完整 |
| `min_coverage_rate` | float | 0.98 | **处理覆盖率红线**（核心阈值）：`(success + failed + skipped) / total`，熔断后未遍历股票计入分母 |
| `skipped_ratio_guard` | float | 0.95 | **休市日 guard**：仅当 `target_date` 非交易日时，`skipped_ratio ≥ guard` 才放行（`is_complete` 第 3 条） |

### 8.2 判定顺序（R-01 第二支柱）

`is_complete` 的判定顺序**严格**为：

1. `total <= 0` 或 `coverage_rate < min_coverage_rate` → **False**
2. 若 `target_date` 为交易日且 `target_date_coverage_rate < min_coverage_rate` → **False**
3. 仅当 `target_date` 非交易日时，`skipped_ratio >= skipped_ratio_guard` → **True**（休市日 guard）
4. 其余按 `success_rate >= min_success_rate and failed <= total_failure_limit`

**约束**：步骤 2 必须在步骤 3 之前，禁止被休市日 guard 短路绕过。

### 8.3 被哪些文件读取

| 文件 | 读取的配置 | 用途 |
|------|-----------|------|
| `scripts/data/update_kline_daily.py` | `min_success_rate`, `min_coverage_rate`, `skipped_ratio_guard` 等 | `UpdateResult.is_complete()` 完整性判定 |
| `scripts/verify_obpc_pipeline.py` | `min_coverage_rate` | 验收脚本覆盖率合规性判定 |
| `scripts/monitor.sh` | `min_coverage_rate` | 告警 1（`check_obpc_coverage`）覆盖率低于阈值 |
| `scripts/scheduler_obpc.py` | 通过 `wait_for_kline_update` → `task_status_allows_run` | 调度器等待 K 线更新完成 |

### 8.4 禁止硬编码

> `min_coverage_rate: 0.98` 是系统级合规红线。验收脚本、监控脚本、调度器中**任何地方**都不得出现 `"0.98"` 这样的硬编码阈值。如需引用此值，必须通过 `yaml.safe_load()` 从 `config/config.yaml` 的 `global.kline_update.min_coverage_rate` 读取。兜底值需与 config 默认值一致，不得凭空另设数字。
