# 数据库设计 V3

## 1. 设计原则

1. **兼容 V2**：klines 表新增 frequency 字段但不影响 V2 查询（设默认值）
2. **务实复用**：V3 直接沿用 V2 的 scan_results 表和 push_history 表，不新建独立的信号表
3. **最小改动**：尽可能复用现有表和索引
4. **向后兼容**：V2 代码无需修改即可正常运行

## 2. 完整表结构（6 张表）

V3 与 V2 共享同一 PostgreSQL 实例的 `schema_stockfilter` schema，共使用 6 张业务表：

| 表名 | 用途 | V3 变更 |
|------|------|---------|
| `stocks` | 股票列表 | 无变更 |
| `klines` | K 线数据 | **新增 frequency 字段，唯一约束调整** |
| `scan_results` | 扫描结果 | 沿用 V2（2026-10-18 新增 `(scan_date, code)` 唯一约束） |
| `positions` | 持仓记录 | 沿用 V2 |
| `push_history` | 推送历史（去重） | 沿用 V2 |
| `scan_runs` | 结构化扫描运行状态 | **2026-10-18 新增**（详见 §9.1） |

## 3. klines 表（V3 唯一的结构变更）

### 3.1 V3 表结构

```sql
CREATE TABLE IF NOT EXISTS klines (
    id SERIAL PRIMARY KEY,
    code VARCHAR(20) NOT NULL,
    frequency VARCHAR(10) NOT NULL DEFAULT 'd',
    date DATE NOT NULL,
    open NUMERIC(10,2),
    high NUMERIC(10,2),
    low NUMERIC(10,2),
    close NUMERIC(10,2),
    volume BIGINT,
    amount NUMERIC(20,2),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(code, frequency, date)
);

CREATE INDEX IF NOT EXISTS idx_klines_code ON klines(code);
CREATE INDEX IF NOT EXISTS idx_klines_date ON klines(date);
CREATE INDEX IF NOT EXISTS idx_klines_frequency ON klines(frequency);
```

## 4. 频率（frequency）字段说明

| 值 | 含义 | 当前使用状态 |
|----|------|------------|
| `d` | 日线 | **活跃使用** -- 所有策略默认频率 |
| `w` | 周线 | 预留，klines 表已支持 |
| `m` | 月线 | 预留，klines 表已支持 |

> **注意**：频率值使用单字符缩写（`'d'`/`'w'`/`'m'`），而非全称（`'daily'`/`'weekly'`/`'monthly'`）。这与旧版设计文档不同。

## 5. 沿用 V2 的表说明

### 5.1 scan_results（扫描结果表）

```sql
CREATE TABLE IF NOT EXISTS scan_results (
    id SERIAL PRIMARY KEY,
    scan_date DATE NOT NULL,
    code VARCHAR(20) NOT NULL,
    name VARCHAR(100),
    score NUMERIC(5,2),
    surge_date DATE,
    support_level NUMERIC(10,2),
    current_close NUMERIC(10,2),
    drop_rate NUMERIC(10,4),
    min_vol_ratio NUMERIC(10,4),
    surge_price NUMERIC(10,2),
    surge_volume_ratio NUMERIC(10,4),
    surge_pct NUMERIC(10,4),
    low_after_surge NUMERIC(10,2),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

V3 通过 `DatabaseManager.save_scan_result()` 方法写入此表。注意：`scan_results` 的字段是围绕超跌反弹策略形态特征设计的，这是 V2 的历史设计。

### 5.2 push_history（推送历史表/去重表）

```sql
CREATE TABLE IF NOT EXISTS push_history (
    id SERIAL PRIMARY KEY,
    code VARCHAR(20) NOT NULL,
    push_date DATE NOT NULL,
    push_type VARCHAR(50),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(code, push_date)
);
```

去重逻辑：`(code, push_date)` 唯一约束确保同一股票同一天不会被重复推送。

### 5.3 positions（持仓表）和 stocks（股票列表表）

沿用 V2 结构，无变更。

## 9. 2026-10-18 扫描可靠性改造补充

本章节补记 OBPC 扫描可靠性整改（R-01 ~ R-14）在数据库层引入的新表、新约束和约定。

### 9.1 新增表 scan_runs（结构化扫描运行状态）

```sql
CREATE TABLE IF NOT EXISTS schema_stockfilter.scan_runs (
    id BIGSERIAL PRIMARY KEY,
    signal_date DATE NOT NULL,
    run_kind VARCHAR(20) NOT NULL,
    status VARCHAR(32) NOT NULL,
    stock_pool_count INTEGER NOT NULL DEFAULT 0,
    scanned_count INTEGER NOT NULL DEFAULT 0,
    raw_candidate_count INTEGER NOT NULL DEFAULT 0,
    selected_count INTEGER NOT NULL DEFAULT 0,
    filter_reason TEXT,
    data_metrics JSONB NOT NULL DEFAULT '{}'::jsonb,
    data_version TIMESTAMPTZ,
    started_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    completed_at TIMESTAMPTZ,
    UNIQUE (signal_date, run_kind)
);
```

**唯一键**：`(signal_date, run_kind)` —— 同一目标交易日的初扫（`run_kind='initial'`）与重扫（`run_kind='rescan'`）互不覆盖，各自幂等。

**状态机**（六种）：

| status | 含义 | 可否表述为"完整扫描后零形态" |
|---|---|---|
| `running` | 扫描进程存活，尚未结束 | 否 |
| `completed_with_signals` | 完整扫描且有最终信号 | 否（直接推信号卡片） |
| `completed_zero` | 完整扫描，原始候选为零 | 是 |
| `blocked_market` | 完成原始检测，风控拦截 | 否（展示原始候选数 + 原因） |
| `blocked_data` | 数据完整性不足，未执行扫描 | 否 |
| `failed` | 扫描异常 | 否 |

**卡死收敛**：调度器启动扫描前调用 `mark_stale_scan_runs_failed(stale_after_seconds)` 将超时未收敛的 `running` 记录置为 `failed`，`filter_reason='stale_running_timeout'`。

**data_version**：记录本次运行依据的 K 线/补全任务 `last_completed_at`（TIMESTAMPTZ），用于重扫幂等判定。

### 9.2 scan_results 表唯一约束

- 新增唯一索引 `uq_scan_results_date_code ON scan_results(scan_date, code)`。
- 迁移过程（幂等，在 `DatabaseManager.__init__` 中自动执行）：
  1. 检查索引是否已存在（`pg_indexes` 视图）；已存在则跳过；
  2. 扫描历史数据，按 `(scan_date, code)` 分组，每组只保留 `created_at` 最新一条；
  3. 打印清理前总数、删除条数、清理后剩余数（审计日志）；
  4. 执行 `CREATE UNIQUE INDEX IF NOT EXISTS ...`。
- `save_scan_result(scan_date, results)` 改为 UPSERT：
  ```sql
  INSERT INTO scan_results (...) VALUES (...)
  ON CONFLICT (scan_date, code) DO UPDATE SET
      name = EXCLUDED.name, score = EXCLUDED.score, ...,
      created_at = CURRENT_TIMESTAMP
  ```

### 9.3 task_status 表扩展

task_status 表由 `scripts/scheduler_kline.py` 首次启动时创建：
```sql
CREATE TABLE IF NOT EXISTS schema_stockfilter.task_status
    (task_name VARCHAR(50) PRIMARY KEY, last_completed_at TIMESTAMP, status VARCHAR(20))
```

2026-10-18 扩展（幂等迁移在 `DatabaseManager.__init__` 中执行）：
```sql
ALTER TABLE schema_stockfilter.task_status
    ADD COLUMN IF NOT EXISTS target_date DATE,
    ADD COLUMN IF NOT EXISTS details JSONB NOT NULL DEFAULT '{}'::jsonb
```

- `target_date`：本次任务实际覆盖的目标交易日（K 线更新的 target_date）。
- `details`：本次任务的完整性指标 JSON（键集由 `update_kline_daily.py --result-json` 的输出定义），至少含 `skipped`、`processed_count`，并含 `target_date_success`。示例：

### 9.4 时间戳约定

**新增列统一使用 TIMESTAMPTZ**：scan_runs 表的 `started_at`、`completed_at`、`data_version`。

**既有 task_status.last_completed_at 保持无时区列（TIMESTAMP）**，这是历史约定：
- scheduler_kline.py 写入时存 UTC 裸时间戳；
- scheduler_obpc.py 读取时用 `row[0].replace(tzinfo=timezone.utc)` 显式赋 UTC 时区；
- 与数据库会话时区（UTC）配合实现 UTC 时间语义。
- **集成测试验证点**：`DatabaseManager` 连接后，`SELECT last_completed_at FROM task_status` 返回的 datetime 对象 `.tzinfo` 为 None，必须通过 `replace(tzinfo=timezone.utc)` 才能与 `datetime.now(timezone.utc)` 正确比较。

### 9.5 股票池过滤：SQL 参数化 + 纯函数双保险

- `get_stock_list(filters)` 完全参数化 SQL（禁止 f-string 拼接配置值）。
- 模块级纯函数 `filter_stock_pool(df, stock_pool_config) -> pd.DataFrame`：
  接受 DataFrame 和 `global.stock_pool` 配置 dict，执行全部过滤开关（ST、退市、北交所、科创板、创业板、新三板、指数、次新股、主板限定）。
  - `get_stock_list` 的 SQL 层先预过滤，**然后调用 filter_stock_pool 做 DataFrame 级最终防线**，确保与固定 CSV 路径经纯函数过滤得到相同股票集合。
  - 调用方式：`from data.database import filter_stock_pool`。
- 禁止在 SQL 层用代码字符串匹配指数（如 `000001`），因为上证指数代码与平安银行股票代码重叠；指数/ETF 必须通过 `name` 或 `sector` 字段识别。

### 9.6 推送幂等查询接口

- 新增 `DatabaseManager.has_pushed(code, push_date, push_type='daily_scan') -> bool`：三列精确匹配，支持同一只股票同日不同推送类型的独立判定。
- 原 `has_pushed_today(code, today)` 保留，向后兼容。
- `save_push_history(code, push_date, push_type)` 保持原签名，底层用 `ON CONFLICT (code, push_date) DO NOTHING`。
