# 目录结构设计 V3

## 1. 设计原则

1. **策略以子包形式**：每个策略一个独立的子包，放在 `strategy/` 目录下（非 `strategies/`）
2. **配置统一**：所有配置集中在 `config/` 目录，一个 `config.yaml` 管理
3. **脚本集中**：运维脚本集中在 `scripts/` 目录
4. **务实路线**：目录只包含实际已实现的模块，"计划中"的模块明确标记

## 3. 与旧版设计的差异说明

| 差异化项目 | 旧版设计 | 实际代码 |
|-----------|---------|---------|
| 策略目录名 | `strategies/` | `strategy/`（单数） |
| 策略文件组织 | 扁平单文件 `strategies/oversold_bounce.py` | 子包 `strategy/oversold_bounce/strategy.py` |
| 信号数据结构 | 独立文件 `strategies/signals.py` | 合并在 `strategy/base.py` |
| 通知层结构 | 多文件：`service.py` + `feishu_notifier.py` + `remote_client.py` | 单文件：`notification/service.py` 二合一 |
| 回测层 | 计划中 `backtest/` 多文件 | 已删除（回测功能移出 V3） |
| E大估值策略 | 无 | 独立策略 `distill_changying/`，含 ETF 推荐引擎 |
| 部署方式 | 单容器 `stockfilter-v3-app` | 3 容器分离：kline / obpc / eadvisor |
| Dockerfile | 单个 `Dockerfile` | 3 个：`Dockerfile.kline` / `Dockerfile.obpc` / `Dockerfile.eadvisor` |
| 依赖文件 | 单个 `requirements.txt` | 按容器拆分：`requirements-kline.txt` / `requirements-obpc.txt` / `requirements-eadvisor.txt` |
| 调度器 | `main.py --schedule` | 各容器独立 scheduler：`scheduler_kline.py` / `scheduler_obpc.py` / `distill_changying/scripts/advisor/scheduler.py` |
| ScanEngine | 计划中 `engine/scanner.py` | 不存在，由 `main.py` 直接调用脚本 |
| StockPoolFilter | 计划中 `engine/stock_pool.py` | 不存在，过滤函数在 `data/stock_list.py` |
| SignalRepository | 计划中 `data/signal_repository.py` | 不存在，直接使用 DatabaseManager |
| StockListService | 计划中 `data/stock_list_service.py` | 合并到 `data/stock_list.py` 函数 |
| BaostockClient | 计划中 `data/baostock_client.py` | 合并到 `data/data_source.py` + `data/fetcher.py` |
| 测试目录 | 计划中 `tests/` 完整分层测试 | 未创建 |

## 4. 模块职责说明

### 4.1 engine/ - 引擎层

| 模块 | 类/函数 | 职责 |
|------|---------|------|
| `registry.py` | `StrategyRegistry` | 策略注册中心，单例模式，支持注册/注销/启用/禁用 |
| `scheduler.py` | `Scheduler` | 多策略调度器，按顺序执行已启用策略，批量加载数据，收集信号，通知 |

### 4.2 strategy/ - 策略层

| 模块 | 类/函数 | 职责 |
|------|---------|------|
| `base.py` | `BaseStrategy` / `Signal` / `DataRequirement` | 策略抽象基类 + 信号 + 数据需求数据结构 |
| `oversold_bounce/strategy.py` | `OversoldBounceStrategy` | 超跌反弹回踩确认策略：大跌->缩量->放量->回踩 四步检测 |

### 4.3 data/ - 数据层

| 模块 | 类/函数 | 职责 |
|------|---------|------|
| `database.py` | `DatabaseManager` | PostgreSQL 连接管理、表创建、V3 迁移、CRUD 封装 |
| `kline_service.py` | `KlineService` | 统一 K 线服务：数据库缓存 -> 远程 K 线服务 -> 本地 Baostock |
| `data_source.py` | `DataSourceManager` | Baostock 数据源管理，获取股票列表 |
| `stock_list.py` | 函数集 | 股票列表过滤（ST/北交所/科创/创业/次新股/指数 等 9 层过滤） |
| `fetcher.py` | 函数集 | Baostock K 线获取 + 数据库缓存 |

### 4.4 distill_changying/ - E大指数估值策略

| 模块 | 类/函数 | 职责 |
|------|---------|------|
| `scripts/advisor/scheduler.py` | 调度器 | E大估值定时调度器：指数估值采集 + ETF推荐 + 飞书日报推送 |
| `scripts/advisor/etf_recommend.py` | ETF推荐引擎 | 基于估值和趋势的 ETF 推荐算法，使用 OpenAI API |

> **注意**：E大估值策略完全不依赖 PostgreSQL，独立运行。

### 4.5 notification/ - 通知层

| 模块 | 类 | 职责 |
|------|-----|------|
| `service.py` | `FeishuNotifier` | 本地飞书 Webhook 通知器（卡片消息/文本消息） |
| `service.py` | `NotificationService` | 统一通知服务（直连飞书 webhook） |

## 5. 包导入约定

```python
# 正确：引擎层导入策略层
from strategy.base import BaseStrategy
from engine.registry import get_registry

# 正确：策略层导入基础类型
from strategy.base import BaseStrategy, Signal, DataRequirement

# 正确：引擎层导入数据层

# 正确：引擎层导入通知层
```
