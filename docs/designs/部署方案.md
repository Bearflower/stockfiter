# 部署方案 V3

## 1. 部署概述

V3 采用 **3 容器分离架构**，每个策略独立容器运行，互不干扰。与 V2 在同一服务器上并行运行。

### 部署架构

```
服务器（Ubuntu 22.04，IP: 10.3.0.12）
│
├── Docker
│   ├── common_service_postgres 容器    # 共享数据库（外部网络 common_service_common_network）
│   ├── stockfilter-app 容器           # V2 应用
│   ├── stockfilter-kline 容器         # V3 K线服务
│   ├── stockfilter-obpc 容器          # V3 OBPC 策略（形态扫描 + 飞书推送）
│   └── stockfilter-eadvisor 容器      # V3 E大估值策略（独立运行，不依赖DB）
│
├── /opt/stockfilter/                  # V2 项目目录
│   ├── docker-compose.yml
│   ├── code/stockfilter/
│   ├── data/
│   ├── logs/
│   └── signals/
│
└── /opt/stockfilter-v3/               # V3 项目目录
    ├── docker-compose.yml             # 3 容器编排配置
    ├── code/stockfilter_v3/
    ├── logs/
    ├── signals/
    ├── .env
    ├── Dockerfile.kline               # K线服务镜像
    ├── Dockerfile.obpc                # OBPC 策略镜像
    ├── Dockerfile.eadvisor            # E大估值策略镜像
    ├── requirements-kline.txt
    ├── requirements-obpc.txt
    └── requirements-eadvisor.txt
```

### 定时任务时序依赖

```
22:00  容器1 (kline):      K线每日更新 -> 写入 task_status 表标记完成
22:15  容器2 (obpc):       等待K线更新完成 -> 形态扫描 -> 写入 scan_results
23:10  容器3 (eadvisor):   E大估值扫描 + ETF推荐 + 飞书日报推送（独立运行，不依赖DB）
07:00  容器1 (kline):      历史数据快速补全（quick_backfill.py）
07:30  容器2 (obpc):       补全后重扫形态扫描
08:10  容器2 (obpc):       读取昨日扫描结果 -> 飞书推送
```

## 2. Dockerfile（3 个独立镜像）

### 2.1 K线服务 - Dockerfile.kline

```dockerfile
FROM python:3.9-slim

WORKDIR /app

RUN apt-get update && apt-get install -y \
    gcc \
    tzdata \
    && rm -rf /var/lib/apt/lists/*

ENV TZ=Asia/Shanghai
RUN ln -sf /usr/share/zoneinfo/Asia/Shanghai /etc/localtime && \
    echo "Asia/Shanghai" > /etc/timezone

COPY requirements-kline.txt .
RUN pip install --no-cache-dir -r requirements-kline.txt

COPY . .

ENV PYTHONUNBUFFERED=1
ENV PYTHONPATH=/app

CMD ["python", "scripts/scheduler_kline.py"]
```

依赖：`requirements-kline.txt`（baostock, pandas, numpy, psycopg2-binary, pyyaml, python-dotenv, loguru）

## 3. docker-compose.yml（3 容器编排）

```yaml
version: '3.8'

services:
  # ===== 容器1: K线服务 =====
  stockfilter-kline:
    build:
      context: .
      dockerfile: Dockerfile.kline
    image: stockfilter-kline:latest
    container_name: stockfilter-kline
    working_dir: /app
    environment:
      - TZ=Asia/Shanghai
      - DB_PASSWORD=${DB_PASSWORD}
      - DB_HOST=10.3.0.12
      - DB_PORT=5432
      - DB_NAME=stockfilter
      - DB_USER=stockfilter_user
      - DB_SCHEMA=schema_stockfilter
      - PYTHONPATH=/app
    volumes:
      - ./logs:/app/logs
    restart: unless-stopped
    networks:
      - common_service_common_network
    command: python scripts/scheduler_kline.py

  # ===== 容器2: OBPC 策略（形态扫描 + 飞书推送） =====
  stockfilter-obpc:
    build:
      context: .
      dockerfile: Dockerfile.obpc
    image: stockfilter-obpc:latest
    container_name: stockfilter-obpc
    working_dir: /app
    environment:
      - TZ=Asia/Shanghai
      - FEISHU_WEBHOOK=${FEISHU_WEBHOOK}
      - DB_PASSWORD=${DB_PASSWORD}
      - DB_HOST=10.3.0.12
      - DB_PORT=5432
      - DB_NAME=stockfilter
      - DB_USER=stockfilter_user
      - DB_SCHEMA=schema_stockfilter
      - PYTHONPATH=/app
    volumes:
      - ./logs:/app/logs
      - ./signals:/app/signals
    restart: unless-stopped
    networks:
      - common_service_common_network
    command: python scripts/scheduler_obpc.py

  # ===== 容器3: E大估值策略 =====
  stockfilter-eadvisor:
    build:
      context: .
      dockerfile: Dockerfile.eadvisor
    image: stockfilter-eadvisor:latest
    container_name: stockfilter-eadvisor
    working_dir: /app
    environment:
      - TZ=Asia/Shanghai
      - FEISHU_WEBHOOK=${FEISHU_WEBHOOK}
      - PYTHONPATH=/app
      # E大估值策略不依赖 PostgreSQL
    volumes:
      - ./logs:/app/logs
    restart: unless-stopped
    command: python distill_changying/scripts/advisor/scheduler.py

networks:
  common_service_common_network:
    external: true
```

### 3.1 task_status 表（时序协调）

K线服务和 OBPC 策略通过 `task_status` 表协调时序：

```sql
CREATE TABLE IF NOT EXISTS task_status (
    task_name VARCHAR(100) PRIMARY KEY,
    last_run_time TIMESTAMP,
    status VARCHAR(20),
    message TEXT
);
```

- K线更新完成后写入 `task_name='kline_update'`, `status='completed'`
- OBPC 策略在每次扫描前等待 K线更新完成（轮询检查 task_status）

### 3.2 单独更新策略

每个策略使用独立 Dockerfile 和镜像，更新某个策略时只需重建对应容器：

```bash
# 仅更新 K线服务
docker compose build stockfilter-kline && docker compose up -d stockfilter-kline

# 仅更新 OBPC 策略
docker compose build stockfilter-obpc && docker compose up -d stockfilter-obpc

# 仅更新 E大估值策略
docker compose build stockfilter-eadvisor && docker compose up -d stockfilter-eadvisor
```

## 4. 与 V2 并行运行方案

### 4.1 资源隔离

| 维度 | V2 (stockfilter-app) | V3 K线 (kline) | V3 OBPC (obpc) | V3 E大估值 (eadvisor) |
|------|---------------------|----------------|----------------|----------------------|
| 容器名 | stockfilter-app | stockfilter-kline | stockfilter-obpc | stockfilter-eadvisor |
| 代码目录 | /opt/stockfilter/code/ | /opt/stockfilter-v3/code/ | /opt/stockfilter-v3/code/ | /opt/stockfilter-v3/code/ |
| 日志 | /opt/stockfilter/logs/ | /opt/stockfilter-v3/logs/ | /opt/stockfilter-v3/logs/ | /opt/stockfilter-v3/logs/ |
| 信号 | /opt/stockfilter/signals/ | - | /opt/stockfilter-v3/signals/ | - |
| 数据库 schema | schema_stockfilter（共享） | schema_stockfilter（共享） | schema_stockfilter（共享） | 不依赖 DB |
| klines 表 | 共享 | 共享（更新写入） | 共享（只读） | 不访问 |

### 4.2 调度错峰（避免资源竞争）

| 任务 | V2 时间 | V3 K线 | V3 OBPC | V3 E大估值 |
|------|--------|--------|---------|-----------|
| K线同步 | 14:00 UTC (22:00 北京) | 14:00 UTC (22:00 北京) | - | - |
| 形态扫描 | 14:10 UTC (22:10 北京) | - | 14:15 UTC (22:15 北京) | - |
| 历史补全 | - | 23:00 UTC (07:00 北京) | - | - |
| 补全后重扫 | - | - | 23:30 UTC (07:30 北京) | - |
| 飞书推送 | 00:10 UTC (08:10 北京) | - | 00:10 UTC (08:10 北京) | - |
| 估值日报 | - | - | - | 15:10 UTC (23:10 北京) |

#### 4.2.1 OBPC 调度时间固化说明（V2.0 最终方案）

OBPC 策略的扫描时间和推送时间已固化为生产环境最终方案，不再调整：

| 环节 | 固化时间（北京时间） | 触发机制 |
|------|---------------------|---------|
| 形态扫描 | 22:15 | 轮询 task_status 表等待 K线更新完成，超时30分钟 |
| 飞书推送 | 08:10（次日） | 定时触发，读取昨日扫描结果 |

**与 V2.0 参数卡片原定时间的差异说明**：

| 项目 | V2.0 参数卡片原定时间 | 生产环境实际时间 | 调整原因 |
|------|---------------------|-----------------|---------|
| 形态扫描 | 15:30 | 22:15 | 需等待 K线服务完成当日数据更新（约22:00完成），15:30 扫描会因当日K线数据未更新而无法识别当日形态 |
| 飞书推送 | 9:15 - 9:25 | 08:10 | 提前至开盘前推送，确保用户在9:30开盘前有充足时间查看信号并制定交易计划 |

此调度时间方案已确认为生产环境最终方案，后续不再调整。详细策略说明参见 [OBPC策略说明文档](./OBPC策略说明文档.md)。

## 5. 部署步骤

### 5.1 服务器端操作

```bash
# 1. 创建 V3 项目目录
mkdir -p /opt/stockfilter-v3/code
mkdir -p /opt/stockfilter-v3/logs
mkdir -p /opt/stockfilter-v3/signals

# 2. 上传代码
cd /opt/stockfilter-v3/code
# scp -r ./stockfilter_v3 user@server:/opt/stockfilter-v3/code/

# 3. 配置 .env
cd /opt/stockfilter-v3
cp code/stockfilter_v3/.env.example .env
vim .env  # 填入 DB_PASSWORD 和 FEISHU_WEBHOOK

# 4. 创建 task_status 表（时序协调用）
# 在 PostgreSQL 中执行：
# CREATE TABLE IF NOT EXISTS task_status (
#     task_name VARCHAR(100) PRIMARY KEY,
#     last_run_time TIMESTAMP,
#     status VARCHAR(20),
#     message TEXT
# );

# 5. 复制 docker-compose.yml
cd /opt/stockfilter-v3
cp code/stockfilter_v3/docker-compose.yml .

# 6. 构建并启动所有容器
docker compose build
docker compose up -d

# 7. 验证各容器状态
docker ps | grep stockfilter
```

### 5.2 常用命令

```bash
# 启动所有容器
docker compose -f /opt/stockfilter-v3/docker-compose.yml up -d

# 停止所有容器
docker compose -f /opt/stockfilter-v3/docker-compose.yml down

# 查看 K线服务日志
docker logs -f stockfilter-kline

# 查看 OBPC 策略日志
docker logs -f stockfilter-obpc

# 查看 E大估值策略日志
docker logs -f stockfilter-eadvisor

# 进入 K线容器
docker exec -it stockfilter-kline bash

# 进入 OBPC 容器
docker exec -it stockfilter-obpc bash

# 进入 E大估值容器
docker exec -it stockfilter-eadvisor bash

# 仅重启某个容器
docker compose -f /opt/stockfilter-v3/docker-compose.yml restart stockfilter-obpc
```

## 6. 监控要点

- 各容器运行状态：`docker ps | grep stockfilter`
- 每日 K线更新是否成功（检查 task_status 表）
- 形态扫描是否按时执行（检查 logs 时间戳）
- 信号数量是否异常（0 或激增）
- 飞书推送是否成功
- E大估值日报是否正常推送
- 数据库连接是否正常

```bash
# 查看 K线服务最近日志
docker logs --tail 50 stockfilter-kline

# 查看 OBPC 策略最近日志
docker logs --tail 50 stockfilter-obpc

# 查看 E大估值策略最近日志
docker logs --tail 50 stockfilter-eadvisor

# 查看主日志文件
tail -f /opt/stockfilter-v3/logs/stockfilter_v3.log
```
