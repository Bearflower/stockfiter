# 股票筛选项目开发工作流

## 开始前

完整读取 `.trae/rules/coding-standards.md`、`.trae/rules/development-workflow.md`、`README.md`、`docs/README.md`，以及任务直接相关的设计、配置和实现。

Trae 规则中的智能体名称仅表示需求分析、实现、检查、测试、文档维护等职责；使用当前可用的 Codex 工具与技能完成这些职责，不能声称调用不存在的智能体。

## 执行要求

1. 明确预期行为、验收条件和不在范围内的内容；检查工作区并保留用户改动。
2. 查找现有模块、配置键、接口和测试模式，优先复用已有依赖与公共模块。
3. 新增或改变行为时先建立可失败的验证；修复问题时先复现。纯配置或文档改动使用结构、引用和场景检查。
4. 最小化实现改动。策略阈值、评分、调度与风控参数必须来自 `config/` 或算法计算，禁止无依据硬编码。
5. 回测、参数优化和大规模数据分析只在本地运行；远程环境仅可导出或筛选数据。
6. 逐项核对导入、调用参数、配置键、文件路径、变量、分支方向、异常路径、同步边界、硬编码来源和文件完整性。
7. 运行相关测试与静态检查；跨模块或高风险改动再运行完整测试。检查行为、配置、部署或操作方式变化是否需要更新 `docs/`。
8. 汇报修改文件、验证命令和结果、未验证部分与遗留风险。不要自动提交、推送或部署。

## 完成检查

- 引用的模块、API、配置键和文件真实存在。
- 测试或等价验证覆盖本次变化，并已观察到有效结果。
- 代码与相关文档一致，未写入凭证或敏感数据。
- 只有用户明确要求时，才切换到 `project-git-workflow` 或 `project-deployment-workflow`。
