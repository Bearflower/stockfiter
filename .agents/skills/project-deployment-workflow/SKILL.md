# 股票筛选项目部署工作流

完整读取 `.trae/rules/deployment.md`、`README.md`、相关部署文档、`docker-compose.yml`、Dockerfile 和现有脚本。部署属于外部写操作，必须由用户明确授权目标环境。

旧规则中的其他项目路径、容器名、服务器地址和 Docker 示例不能直接套用。无法从当前配置或用户信息确认主机、认证方式、远端目录、服务、健康检查或回滚方案时，停止并请求必要信息。

1. 确认仓库版本、环境、主机、远端目录、部署方式、目标服务、健康检查与回滚方案，记录部署前状态。
2. 检查工作区、版本和相关测试。禁止在生产服务器运行回测；远程数据只导出到本地。
3. 使用仓库真实方式打包或构建，排除 `.env`、密钥、数据库、日志、缓存与本地产物；生成可核验的版本标记和关键文件摘要。
4. 上传后比较本地与远端产物摘要；不一致时立即停止。
5. 使用真实的 Compose 服务名构建和启动：`stockfilter-kline`、`stockfilter-obpc`、`stockfilter-eadvisor`。构建失败不得继续启动旧镜像。
6. 核对目标容器实际使用预期镜像、版本标记与关键文件摘要；存在卷挂载时同时核对宿主机来源。
7. 运行最小健康检查或烟雾测试，检查新启动后的错误日志和关键调度开关。
8. 汇报环境、版本、摘要、容器状态、健康检查、未解决警告与回滚点。任何关卡未验证都要明确标记，不能推测成功。
